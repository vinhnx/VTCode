# Ratchet baseline for the tiered Rust file-length gate
# (scripts/check_rust_file_length.py, src tier: warn 500 / enforce 800).
#
# This is the debt ledger for src-tier files already over the 800-line enforce
# budget when the gate was adopted. Rules:
# - Entries are `path=CAP` with CAP = the file's size at adoption; globs are
#   allowed but discouraged (exact paths keep the ledger reviewable).
# - Caps only ever ratchet down: growing a file past its cap fails the gate.
# - When a file shrinks below 800 lines (or is renamed/deleted), its entry
#   goes stale and MUST be removed in the same change; stale entries fail.
# - Never add first-party source without a split plan; vendored/generated
#   trees are excluded by the gate itself, not listed here.
# - Test-tier files (tests.rs, *_tests.rs, tests_*.rs, tests/, benches/,
#   fuzz/, examples/) are NOT baselined; they enforce at 1000 lines directly.
# - Re-snapshot candidates: `python3 scripts/check_rust_file_length.py
#   --emit-baseline` prints the current `path=lines` set; merging it into
#   this ledger must never raise an existing cap.
#
# Split targets, worst first: desktop view/*, runloop turn/tool_routing,
# vtcode-llm providers, vtcode-ui widgets.
#
# Cost of the function-level complexity ledger: each annotated function
# carries one `#[expect(clippy::cognitive_complexity, reason = "...")]` line
# (four when the expectation is feature-gated for `profiling`). Those
# lines are part of the debt these caps cover, so the eleven files that
# gained one moved up by exactly that many lines on 2026-11-15 — the
# whole raise is annotation, and the split plan each annotation names is
# now the only way those caps come back down.
