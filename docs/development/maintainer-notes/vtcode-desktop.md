# vtcode-desktop maintainer notes

Detailed contracts and gotchas for `crates/codegen/vtcode-desktop/`, moved verbatim from its [AGENTS.md](../../../crates/codegen/vtcode-desktop/AGENTS.md). Read the section for the subsystem you are changing.

[Root AGENTS.md](../../../AGENTS.md) | macOS-only (Apple silicon) GPUI Kit (`=0.10.0`, `gpui-pre 0.3.12`) app; modules: `view/` (screens), `files/` (snapshot, fuzzy search, launch/mutate), `themes/` (tokens), `preferences/`, `transport.rs`, `localization/`, `app_icon.rs` (artwork + Dock).

## Hard rules

- WCAG AA 4.5:1 for foreground + every accent vs background in all themes (`every_theme_*` tests + `cargo nextest run -p vtcode-ui -E 'test(theme)'`); focus indicators get their own contrast check apart from text.
- All user-facing strings localized (`rust_i18n::t!`, 20 locales, args match `%{...}` placeholders); keep whole translated messages — never append hardcoded English fragments to `t!` output (`view/chrome.rs` swipe tooltips use `app.navigation.{back,forward}_swipe` keys); locale data lives per-surface in `locales/app.<ns>.yml` (one line per key, `_version: 2` first line, no trailing whitespace in values); GUI tests use `#[gpui_kit::test]` with stable `ElementId`s, `lock_scroll_axis()` before `.test_support()`, and `set_reduce_motion(true)` for overlay-click flows (opacity fades stay clickable); multi-step pointer/key gestures use `TestEventExt` (`pointer_down`/`pointer_move`/`pointer_up`, `key_down`/`key_up`) instead of hand-built `PlatformInput`, raw dispatch stays only for `click_count > 1`, an explicit modifier on the press itself (shift-click), or explicit scroll phases, and disabled controls are verified by attempting the interaction and asserting the application result (a `Some(true)`/`None` `disabled()` flag alone is not proof).
- Every action keyboard-reachable with visible focus; overlays dismiss via `dismiss_overlay` paths and restore focus (`*_return_focus`), new overlays must also bind Escape on the topmost surface and be dropped when `open_settings`/`activate_composer` can mount another route beneath them; rail selections use `desktop_selected` on `secondary` surfaces; rails on a `popover` panel (e.g. the license viewer) use `secondary`; icon-only controls carry an accessible name (+ tooltip when scope needs explaining); never encode meaning by color alone; use result labels such as `Delete` and `Cancel` and native `Delete "Name"?` confirms (`[Destructive, Cancel]`, `matches!(answer.await, Ok(0))`, untestable headless); Full-access consent instead uses the in-app modal (`view/full_access_confirm.rs`, checkbox-gated Confirm + one-shot `fullAccessConfirmed` attestation, headless-tested); `Switch` for immediately-applied settings.

## Best practice

- Compose from `view/components.rs` (shared button builders, `desktop_folder_tab_bar`, `settings_row`, `settings_group_box`, `accessible_group_box`, `centered_empty_state`, `pane_divider`, `nav_group_header`, `card_border_style`, `track_focus`, shimmer labels, turn pending row, `severity_marker`/`loading_marker_row` severity/loading rows with test identity kept on the caller wrapper, `modal_scrim`, `consent_title_row`); same-kind overlay openers toggle via `toggle_palette_kind`/`toggle_settings` (second trigger closes); rem scale (`text_sm`, `gap_2`, `p_4`) and component `Size` APIs over `px()` (pixels only for hairlines, platform insets, hit-test tolerances, and fixed pane/region geometry); `truncate()` long/dynamic text; mono font only for code/ids/shortcuts/aligned numbers; load the `gpui-kit` (coding guides) and `gpui-kit-design-guides` (design guides) skills via `read_skill` before UI work, follow their review checklists, and check `docs/development/desktop-component-review.md` before introducing a component (Applied/Retained/Not-needed decisions stand).
- Workspace tag filter: `desktop/project_tags.rs` owns validation/persistence state (workspace path -> tags, plus active filter) and `view/project_tags.rs` owns the popover, manager, and `context_sessions()` projection. The projection borrows the raw list when no filter is active and allocates only under a filter — never cache a second session list or tests that seed `sessions` directly will silently render stale rows. A newly added workspace inherits a tag only when exactly one is active and the path is genuinely new; stale active tags are pruned at load. The tag map is derived from `recent_workspaces` (capped at 8), so it must be retained on load and on every workspace touch — otherwise evicted projects leave phantom tags and filters that match nothing. Kit's controlled `Popover` does not announce prop-driven closes, so reset the search input on both open and close. The manager paints above the confirm modals, so its `dismiss_overlay` arm precedes them. The sidebar Tags section is a disclosure: radio rows pick one context (re-clicking the selected one is a no-op via `select_tag_context`, not the picker's toggle) and "All Tags…" opens a second picker anchored to that row. The quick list is capped at `MAX_SECTION_TAG_ROWS` with active tags promoted first, since the sidebar's thread list is a `flex_1` region; the picker still lists every tag. Both pickers share `tag_picker_content`/`tag_filter_popover`, so only one may be open (enforced in `on_open_change` and at render); `open_tag_manager` and section collapse must close them before a modal scrim mounts. Tag labels use Kit `Tag` through the one `project_tag_chip` helper: neutral chips take `secondary`/`foreground`/`soft_edge_color`, selected chips take `primary`/`filled_button_foreground`, and chips stay pill-shaped with truncation — no per-tag colors, because tags are labels rather than status. Kit `small()` forces a 0.625rem label, so chips reapply `text_xs()` (the app's minimum tier) and use rem-based max widths to track the UI font setting.
- All Desktop fades share `view/motion.rs`: `fade_timing`/`fade_animation` are the single duration/curve source for `FadeInExt` and `NavigationFadeExt`, and `opacity_fade` is their one wrapper (id = playback identity; an app-owned generation, or a remount, is what replays a one-shot); do not add a second easing, animation builder, or opacity animator. `NavigationMotion` samples opacity with absolute time, resumes a retarget from the last sampled value instead of flashing to transparent, shortens the remaining duration (15% floor), and requests frames only while moving. Reduced motion snaps to the end state through gpui-fast `with_animation` or the early return in `NavigationMotion::fade`; the OS/app preference stays in `preferences.rs` (the Kit preference swap was reviewed and rejected: macOS-only app, no live system updates).
- Icon sizes follow the desktop tier table (all rem-based, so they track the UI font setting 14–24, default 16): bare `Icon::new` matches surrounding text (titles, button labels); `.small()` (14px @ 16rem) for dense rows, markers, tabs, and palette leading slots; `.size_4()` (16px) for input prefixes and nav labels; `.size_6()` (24px) for empty-state and attachment media only; `Button.icon(..)` is Kit-owned (it re-sizes the icon to the button size — never override). Reuse `transcript_icon_slot` for fixed leading slots and `files_panel::file_tree_row_icon` for file rows; register non-default glyphs in `ExtraIcons` (`desktop/assets.rs`); `every_icon_referenced_by_the_ui_resolves_through_desktop_assets` token-scans all `src/**/*.rs`, so an unregistered `IconName::` usage fails in tests without false hits from comments or string literals. `view/palette.rs` nears the 1000-line ceiling (949 before the file-path command): new palette helpers go in `view/palette/` submodules (see `icons.rs`).
- States visible and honest: distinct hover/focus/selected/disabled/loading; spinners in `muted_foreground`; shimmer labels only while genuinely loading (skeleton viewers were removed in favor of shimmer text); disable submission in flight; errors scoped near the action (`colors.danger`, `text_sm`); keep views free of service/runtime logic. Shimmer color is builder-owned: pass the semantic tone to `shimmer_label`/`loading_marker_row(_with_spinner)` and let it derive the resting/highlight pair (`themes::shimmer_resting` + palette foreground) and the reduced-motion full-tone fallback. Never set a shimmer's `.text_color()` at the call site or leave the band to Kit's default derivation.
- Thin response routers: method match arms delegate to `apply_*`/`fail_*` beside the feature's request builders; failed responses route through `view/backend_events/response_error.rs` (`handle_response_error`), which owns each method's failure surface (pane-level error, silent acknowledgement, or the generic banner); `fail_pending_navigation()` on async errors; confirm destructive service calls natively and enforce server-side (service validates, client guards).
- Performance: memoize projections per revision/epoch (transcript revision, config catalog epoch, inspector); page long lists (20 rows + `Show more (N remaining)`); virtualize measured rows; remeasure only on typography/theme changes; blocking work via `background_spawn`; no I/O or unbounded loops in render fns. List readers are unsettled before first layout (gate overlay visibility on `transcript_layout_settled`); `on_next_frame` never runs headless (scroll synchronously, assert exactly).
- Retained text is shared, not copied (GPUI Kit SharedString page, CC BY 4.0; pinned 0.10.0 wins): `view/palette.rs` keeps `PaletteCommand::{label, description, accessible_label}` and `PaletteGroups` group labels as `SharedString`, because `palette_render.rs` clones the whole group table on every frame into `'static` Kit row closures. `accessible_label` (`label · description`) is derived once in `share_palette_commands`, not formatted per row per frame; do not revert these fields to `String` or add a second copy of message/config text per row. Other derived-once handoffs: `markdown.rs`/`view/interaction_render.rs` clone `prepared.accessible_text` (never `.to_string()` into a fresh `SharedString`), `view/workspace_review.rs` stores `patch_text` beside the protocol snapshot and clones it in the raw-diff fallback (the patch can be large), and `view/typography.rs` keeps the displayed font family as one `SharedString`. Static UI literals retained across frames use `SharedString::new_static` consts (`transcript_activity.rs`, `settings_computer_use.rs`, `computer_preview.rs`, `shortcuts_render.rs`, `settings_vtcode.rs`, `queue.rs`) instead of `.to_string()` per render. Cloning short inline `SharedString`s copies bytes, so only heap-backed values share a backing pointer — do not assert pointer identity on short fixtures. Do not put a GPUI type in `vtcode-desktop-protocol` to "fix" wire text — the shared DTO stays GUI-agnostic.
- `cx.notify()` is equality-guarded on continuous controls: it repaints the whole `DesktopView`, so the tree subscribers only notify when `track_tree_expansion` reports a real set change, the effort-slider observer only when `SliderValue` differs (Kit notifies even for equal dragged values), the custom-theme color picker only for a different color (still clears a stale validation error), `view/backend_events/thread_events.rs::handle_ui_progress` only when the `ui_progress_active` boolean actually flips, `handle_thread_event`'s `GoalUpdated` arm only when the snapshot differs (so per-turn refreshes keep the original arrival stamp and the live-elapsed label does not restart — `view/tests/goal_bar.rs::repeated_goal_snapshot_keeps_the_original_live_elapsed_stamp`), and `UpdateInstallProgress` only when the displayed phase changes (`backend_events/handle.rs` compares before applying; `view/tests/notifications_install.rs::duplicate_install_progress_ticks_do_not_notify`). These value guards are adapted from the GPUI Kit FPS Monitor's INV lesson (CC BY 4.0): a duplicate notification must not add a second `notify` at the handler boundary. The drain is now mutation-driven (`view/backend_events.rs::drain_events`): each `process_drained_event` returns a change signal and the drain notifies only when a handler actually mutated state. `handle_backend_event_tracked` returns `bool` with a conservative `true` default — every arm that is not a proven stale/parse/no-op guard keeps the old invalidation, so a newly added event can never render a stale UI. `ThreadEvent` deliberately stays conservative because a tool-output delta feeds the read-only terminal monitor (`thread_events.rs` `feed_output`), whose grid has no shell pump and depends on this repaint; `view/tests/backend_drain_notify.rs` pins no-op, genuine-change, and monitor cases through the real drain. The goal guard additionally preserves the arrival stamp for byte-identical snapshots; the per-turn producer advances `elapsed_ms`, so that is a defensive boundary case. Do not claim a frame-rate win without a profiled build. Deliberate exception: the custom-theme **name** input must keep its per-`Change` notify because the preview label reads the live `InputState` during render — do not "optimize" it away. Do not reintroduce per-event notifies in `process_drained_event`: the drain owns the single notify per batch, and a handler that adds its own should also report `true` so the signal stays conservative.
- Entity handle ownership (adapted from the GPUI Kit Entity guide, CC BY 4.0; pinned `gpui-pre 0.3.12` source wins): `cx.listener`/`observe`/`subscribe` capture a **weak** view handle, but `cx.processor` captures a **strong** one (`app/context.rs::processor` calls `self.entity()`) — the sole use is the transient `MessageScroller` renderer in `view/transcript_render.rs`, which is consumed in the same render pass and never stored back on `DesktopView`, so there is no cycle. If a processor closure ever lands in a retained field or the view's own entity, downgrade it first. Keep child→root back-references weak (`ThemeGrid`, handoff, deeplinks, `MainWindow` global); retain every `Subscription` in the subscriber; hold or explicitly detach every `Task`; when a read feeds a same-entity `update`, prefer `read_with` so the read boundary is explicit (the older statement-level `read(...).value()` form was already NLL-safe — this is readability, not a panic fix). Per-drag `cx.new` in `view/resize.rs`/`view/inspector_panels.rs` is mandated by Kit's `Render`-typed drag preview, not a state reset in render.
- Layout persistence is one write per interaction: pointer splitter drags save on drop, and splitter arrow keys defer the fsync-backed `preferences.json` write to key release through `layout_save_pending` (key repeat delivers many key-downs per physical press). Any `save_preferences()` call retires the pending flag and writes the current sizes; the slider path follows the same Release rule. Never restore a per-key-down save — `write_private_file_atomic` ends in `sync_all`.
- Motion policy: every one-shot UI transition stays under 300ms and ordinary chrome appearances use the ease-out-shaped enter curve. Destination navigation uses accelerating reveals for opening and decelerating reveals for returning — fades consume `MotionTokens` (`duration_fast`/`duration_normal` + `easing_enter`) via `zen_fade_animation`, and streamed transcript chunks fade over `STREAMING_FADE_MS` (280ms, Kit's own streaming preset) with `Easing::EaseOut` and zero stagger; `shared_motion_tokens_stay_within_ui_animation_policy` + `streaming_markdown_fades_chunks_without_word_stagger` pin the ceiling and the curve shape, and `with_animation` renders the end state under reduced motion with no manual gate. The composer caret uses the native OS blink: the desktop projects `Theme::cursor_blink` through component `Theme::update` — Kit's default blink under normal motion, `steady()` under reduced motion — and no application-owned fade runs; `caret_blink_follows_effective_reduced_motion` pins it.
- Pending workspace navigation survives transient gate contention: a refused `SESSION_LOAD` send keeps `pending_navigation` armed while the gate is held and retries after the freeing response is fully handled, instead of failing the handoff (an in-flight permission restore used to win this race and silently drop CLI `/desktop` session links). Retries wait out an in-flight switch and an unlanded list (`session_list_received`); refusal with a free gate (running turn, retained draft) and terminal conditions (target gone, workspace mismatch, session missing from a landed list) still fail fast. Pinned by the `handoff_*` tests in `view/tests/session_link.rs`.
- Transcript human-projection policy: `TranscriptItem.output` always holds human text — every store routes through `output_sections::human_output_text`/`human_output_option`, which strip the `Structured output:` JSON envelope core appends for the LLM (only `spool_note` prose survives) and collapse blanks to `None`; renderers (`markdown::render_output_text`) never see raw JSON, so never add a JSON branch there. Row titles, detail lines, session labels, and harness visibility all delegate to `vtcode-commons::{tool_headlines, tool_intent}` (shared with the CLI since the dedupe; new `HarnessEventKind`s must pick a visibility side at compile time there, failures/blocks stay, unknown names take the `humanize_tool_name` fallback, multi-line commands preview to the first line like CLI compact rows). Only surface composition stays local: verb categories and `Ran {cmd}`/`Search code for {q}`/`Grep {p} in {path}`/`List files in {loc}`/`Fetch {url}` gist routing, `gist_keys`/`extra_gist_keys` title-consumed keys so details never echo the title, `ToolOutput` merging into any row its `call_id` names (orphans keep the standalone fallback), and single-line title collapse. Edit rows join per-call `+A −D` stats from their `{call_id}:changes` FileChange sibling (live path only; restored rows keep plain/generic titles). Pinned by `human_output_*`, `output_text_*`, `tool_output_merges_*`, `gist_*`, `edit_stats_*`, and `multi_line_*`/`completed_commands_*` tests here plus the commons suites.

- Soft edges are one knob: surfaces that used to paint full-strength `colors.border` (dialogs, cards, pills, dividers, code panels) now use `themes::soft_edge_color` — the `border` token at 0.55 opacity — so boundaries read as quiet hairlines in every theme; tune the opacity there, never per surface. Contrast-derived `themes::hairline()` is a separate recipe that stays wherever a border must clear a floor on its own fill (composer, change-summary cards, theme swatches, terminal preview chips) — do not swap the two. Keep `border`/`input` opaque for Kit inputs and keep focus rings and semantic (`danger`/`success`) borders at full strength for contrast. `soft_edge_is_the_single_translucent_border_tone` and `card_border_style_pins_a_1px_theme_border` pin the contract.
- Welcome/zen empty state is a compact signature on the composer spine (`view/transcript_render/welcome.rs`): the brand V, one `soft_edge_color` 1px hairline, and the localized greeting share a single centered row; the measured `welcome-brand-mark` id starts at the composer's left edge and the workspace/connecting context keeps its own row below so validation cannot shift the heading. Never stack the mark above the greeting or move the composer to make room — `welcome_signature_is_one_compact_row_on_the_composer_spine`, `welcome_greeting_stays_aligned_with_the_composer_when_toggling_zen`, and `connecting_status_keeps_the_welcome_greeting_in_place` pin the geometry.

## Button roles

Use the shared builders in `view/components.rs` for push buttons.

| Role | Builder | Use |
| --- | --- | --- |
| Primary | `desktop_primary_button` | Main action in a decision area, such as Save, Send, Import from CLI, or Check for updates. Uses the opaque theme accent at rest. |
| Secondary | `desktop_secondary_button` | Ordinary visible action or a companion to Primary or Danger, such as View release notes, Browse, Cancel, or Retry. |
| Danger | `desktop_danger_button` | Destructive commitment or explicit risk acceptance, such as reset, deletion, or Full access. Uses the fixed deepened Ciapre red (`#9B2C2C`, dark enough for the `#CCCCCC` label to hold AA). Keep the owning confirmation flow. |
| Ghost | `desktop_ghost_button` | Quiet toolbar, inline, and navigation actions, such as transcript copy, expand, and tab close. Use `desktop_dismiss_button` for an X with a shared accessible name and tooltip. |

- Use semibold for Primary and Danger labels, medium for Secondary, and regular weight for quiet Ghost actions.
- The composer's option triggers (attach, model, effort, mode, policy) are `desktop_ghost_button` — quiet text buttons with hover state only and no filled pill bodies — while the single main action (send / queue / cancel-turn) is a `desktop_primary_button` with a full radius, so the next action stays unmistakable on every composer row. Keep their accessible names, tooltips, sizes, and action wiring when touching that row.
- Use one Primary per action group. In About, Install Update takes priority when a release is offered. In Shortcuts, Save takes priority while a draft is being edited.
- Apply `desktop_disabled` to push buttons to set the disabled cursor and clear instance shadows. Kit supplies hover, press, disabled, and focus paint.
- Use `desktop_ghost_button` with `desktop_selected` for persistent choices with selected-state paint. Keep Kit tabs, toggles, switches, and native dialogs in their own components.
- Primary and Danger share a soft neutral shadow and subtle inset edges. Preserve each surface’s button size, accessible name, tooltip, focus behavior, and action wiring when changing roles.
- Filled labels come from `themes::filled_button_foreground`: softened ink (`#171C26` dark / `#CCCCCC` light) at the luminance crossover, with a dead-band rescue toward the pure pole when a seed falls between the two AA floors. State ramps blend toward `filled_state_pole(label)` — `mix()` moves lightness only, so deriving the pole through the label derivation collapses hover onto rest (pinned by `primary_state_ramps_*`). Default/secondary fills seat one step above the panel surface (`apply_filled_surfaces`) so quiet buttons keep a visible body on settings pages, and the hover plus Secondary press derive from that same seat (`apply_unified_hover_surface`); the canvas hover/press steps would otherwise sit beneath the lifted fill. The ring token stays transparent (no focus-ring borders) and the caret carries keyboard focus.

## Typography & accessibility

- Hierarchy via the `components.rs` label ladder — `content_page_title` (`text_2xl`), `panel_title` (`text_lg`), `section_label`/`group_box_title` (`text_base`), `row_title` (`text_sm`), `eyebrow_label`/`row_description` (`text_xs`) — with `text_sm` body and `text_xs` metadata; `muted_text` for secondary info, `aa_muted` captions-only; semibold marks structural labels and active/emphasis states, medium marks emphasized values, regular is prose; `label_ladder_keeps_every_tier_distinct` pins the ordering at small/default/large base fonts; verify roles/labels in the test tree (`role()`, `label()`); container aria labels need `role(Group)`; type scales with the user's text-size choice, so verify zoom at several base fonts (wrapping, truncation, pane minima, virtual-list measurement, focus-ring clearance) and keep longer translations from clipping or shifting sibling spines.
- Dynamic errors use `components.rs::accessible_error(id, message, colors)` — stable id, `test_support`, `Role::Alert`, `aria_label` equal to the visible text, shared `text_sm` danger size. Never render a request failure as a bare danger-colored `div`: color alone is not an announcement. Every `Role::Status`/`Role::Alert` node also needs an explicit `aria_label` bound to the same string it paints — nested text alone yields `label() == None` in the painted tree (verified by TDD on `shortcut-empty`, `config-write-notice`, `history-page-limit`). A composite control has ONE Tab stop: the contrast slider's wrapper owns focus + `Role::Group` + `aria_label`, and the Kit `Slider` child sets `.tab_stop(false)` while keeping value/range/actions; two stops would let arrow keys change the value without the wrapper's persistence. Repeated-item ids track their card (`mcp-app-error-{item}-{index}`); never reuse one id across previews. Selectable rows key by domain identity, never array position: `render_question_step` uses `interaction-question-choice-{choice.id}` like the other choice paths (positional indices stay only for aria set position, digit shortcuts, and prepaint bounds), pinned by `wizard_choice_identity_follows_the_choice_id_not_its_slot`. Controls that open an external URL set `.role(Role::Link)` (Kit's Button role is a11y-only, so appearance, click, and keyboard behavior are unchanged); application commands stay `Role::Button`.
- Theme tokens only: no hex/`rgb()`/`hsla()` outside `themes/`; read `cx.theme()` by semantic role (`background`/`foreground`, `muted`, `primary`, `danger`/`warning`/`success` only for their meanings; `chart_*` for categorical segments); floors: secondary copy targets 6:1 where headroom allows, muted text holds 5.0 (AA 4.5 is the absolute floor), chrome 3:1 (`faded_chrome`, `label_foreground`, `tab_foreground`); fills take the weakest separating step with raised keeping a gap above resting while hover takes the strongest readable step; derive via `readable_semantic_color`, `readable_indicator_color`, `accessible_focus_color`, `filled_button_foreground`; verify light + dark, never assume fg/bg polarity; sRGB holds on Display P3 via macOS color management (wide-gamut authoring blocked on kit support; `every_theme_stays_within_srgb_gamut` guards it).
- Transcript paragraph contract (desktop owns style constants + column, Kit owns layout): 1.6 body leading (≥1.5 WCAG floor, asserted in `markdown.rs`), 1rem paragraph gaps, left-aligned ragged-right always — GPUI `TextAlign` has no justify variant, and full justification harms narrow-column readability, so there is no desktop justify path to add. Hanging list markers, heading tiers, quote rails, and syntax token colors are Kit defaults VT Code does not override (code font/size/background are set in `markdown.rs`). Column caps come from the Settings → Appearance → Layout "Chat width" preference: `Comfortable` (the default) is 768 normal / 680 zen, `Wide` is 1200, and `Full extend` uses an effectively unbounded `max_w` so the column fills the conversation area while sidebar/inspector stay flex siblings. The comfortable zen cap keeps its 2rem title-spine inset per side on assistant prose (~88/~77 chars at default size on a 0.5-advance proportional basis); normal fits ~80-col code, zen trades it for focus (see the `view/overlays.rs` const comments for the measured math). `content_width()` in `view/overlays.rs` is the single resolution point every cap consumer calls. Long tokens break mid-token and wrap instead of clipping, staying inside the column on prose, notice, tool-output, fenced-code, and wide-table surfaces, with accessible text intact (`unbreakable_text_stays_inside_transcript_bodies`, `assistant_prose_measure_follows_the_column_minus_title_inset`, `wide_tables_stay_inside_the_conversation_column`, all in `view/tests/transcript_readability.rs`).
- Deliberate CLI divergence on the same readability intent: the TUI justifies agent prose (`justify_wrapped_lines_in_place`, non-last single-span lines only, never code/lists/links/diffs) and separates paragraphs with one deduped blank row (`push_blank_line`); desktop keeps the rag and the rem gap because its renderer cannot justify. Do not "sync" either side toward the other's mechanics — sync the intent (one gap between paragraphs, hanging continuation indents, no stacked separators, unbreakable content stays in its surface).

## Gotchas

- Tabs are chosen by semantics, not looks: `desktop_folder_tab_bar` for document strips (thread/inspector, joined to content) and `desktop_segmented_tab_bar` (Kit `TabVariant::Segmented`, compact) for mutually exclusive choices (attachment source, reduce motion, history scope). Kit 0.10.0 tabs join a roving-focus list by default, so every desktop bar sets the vendored `keyboard_navigation(false)` and `segmented_choice_wrapper` stays the single canonical host: it owns the lookup id, focus handle, focus ring, click-to-focus, and clamped Left/Right/Home/End navigation through `segmented_choice_index`. The "bland" settings row was hand-built ghost buttons; the "notch" attachment tabs were folder tabs in a popover with no content to join. `themes/fills.rs` already derives the segmented track/foreground tokens, so no new palette values are needed. Static settings renderers must not read the view entity during render (reentrant `update` panic) — pass the focus handle through props like `contrast_focus`. Tests address tabs by wrapper id + index and assert `.selected()`/`.label()`, not per-tab ids/`.checked()`. Because the wrapper is the only focus stop, it carries `Role::Group` and an `aria_label` naming the current value (the inner Kit tabs carry `Tab`/`aria_selected` but never receive focus). Kit's `Button::tooltip(text)` shorthand is `Button`-only in 0.10.0 (same as 0.9.1), but `Tab` is a `StatefulInteractiveElement`: attach tooltips with the public fluent `.tooltip(|window, cx| Tooltip::new(text.clone()).build(window, cx))` and import `gpui_kit::component::tooltip::Tooltip`. The per-option reduce-motion tooltips are preserved that way.
- Nav tracks cap three pinned icons per track: the rail keeps Home/New/History and the toolbar keeps Search/Zen; everything else goes through the data-driven `NavMenuAction` overflow builder in `view/navigation.rs` (`nav-overflow` for the rail, `header-overflow` for the toolbar). Overflow-only actions have no clickable element id, so tests either dispatch the corresponding view method (`toggle_settings`, `toggle_inspector`, `open_utilities`, `set_navigation_visible`) or open the overflow trigger and find items by index — Kit's popup items expose `label`/`aria_toggled` but NOT an a11y `disabled` flag, so disabled-state gates must be asserted on the view method (`new_thread_available`), not the menu item. `view/tests/nav_track.rs` pins the cap, item lists, and state labels.

## Embedded terminal

- One login shell per workspace (`terminal_process.rs` spawn/close, `terminal_screen.rs` Rio grid wrapper, `terminal_tab.rs` retained session, `view/terminal_panel.rs` toggle/pump/render/input). User guide: [desktop-terminal](../desktop-terminal.md) + [quick reference](../desktop-terminal-quick-reference.md). Not an agent tool: no harness events, no `ThreadEvent`, no sandbox relationship — keystrokes are the user's, output is untrusted.
- Palette sync funnels through `sync_terminal_palette` (theme, contrast, and setting changes); `apply_theme_state` must store the new `theme_mode` BEFORE syncing or Auto resolves against the stale mode. ANSI default fg/bg/caret follow the theme; the 16 dark slots keep Rio's defaults and the 16 light slots live in `themes/terminal.rs` (hex lives under `themes/` by the hard rule) and hold 4.5:1 on every built-in light theme — test against `all_themes()`, never a single assumed ground (`hybrid-light` 0xE4E4E4 is darker than latte and broke the first table). Palette tables are parse-once `LazyLock` statics (`default_list()` in `terminal_tab.rs`, slot arrays in `themes/terminal.rs`): rio-vt `from_hex` compiles two regexes per call with no cache, so the five per-frame scheme previews cost ~50ms/frame until cached (samply 2026-11-12: open-marginal 50ms → 2.7ms debug). Never rebuild palettes in render; `apply_chrome_slots` stays per-call (pure math over live theme colors).
- Output-trust boundary (`may_forward_to_view` + `terminal_reply` + pump): clipboard OSC-52 is dropped both directions, device/size/color queries answer to the PTY only, bells/titles/cwd forward to view events the pump drops (no surface yet). Every event routes exactly once — pinned by `terminal_drain_routes_every_probe_exactly_once`. The tab label reads Rio's stored OSC 7 directory at render time rather than consuming the event, and `terminal_short_dir` strips control characters from the shell-controlled text.
- Drain bounds are load-bearing: Rio emits one event per BEL with no coalescing (measured 8KB → 8192 events), so view events cap at 256/batch (`MAX_VIEW_EVENTS_PER_DRAIN`, engagement proven by the bell-flood test), PTY events at 64, scrollback at 10k lines, reads at 8KB. Never grow these without re-running the flood tests.
- The pump loop task must stay retained (`terminal_pump_task`): dropping a GPUI `Task` cancels it, and a fire-and-forget spawn froze the real panel while every manual-pump test stayed green. `terminal_pump_loop_ticks_without_manual_pumps` advances the headless clock and asserts drained output with no manual pump — the only test that exercises the spawned loop.
- `close()` kills the shell's foreground process group and reaps the shell (pinned by the process-group test); detached background groups the shell disowned may survive — documented on `close()`, not fixable from the panel.
- Mouse-drag selection maps through a zero-size origin-probe element (`TerminalOriginProbe`, first grid child): GPUI exposes no element-bounds lookup, so the probe stashes its paint-time origin into a view-owned `Rc<Cell<...>>` each frame and handlers divide by measured row height/`M`-advance column width. Drags rebuild the Rio range from scratch each move (incremental updates keep a stale anchor side and drop the anchor cell on backward drags); a buttonless move self-heals a release-outside-the-panel stuck drag without clearing. The probe also reports content width, so the pump syncs grid columns from `floor(width / M-advance)` (spawn holds 80 until the first paint).
- Headless terminal tests: `cargo nextest run --locked -p vtcode-desktop -E 'test(terminal)'`; theme/palette/i18n coverage joins via `or test(theme) or test(contrast) or test(palette) or test(copy_resolves)`. New ANSI settings copy stays English-only in `localization/tests_untranslated.rs` until all 20 locales ship.
- The grid is not test-owned: the session is a real login shell, and the macOS prompts (`/etc/bashrc` `PS1='\h:\W \u\$ '`, `/etc/zshrc` `%1~`) print the workspace path, whose `tempfile` suffix carries random uppercase letters. ## Typed string vocabulary (2026-11-20)

Closed-set identity strings use the owning enum or the tables in `src/desktop/strings.rs`; only single-use data/identity grammars stay inline. This extends the localization rule ("data/identity strings stay hardcoded") to typed values — a raw literal is fine at a single producer, but two-way contracts need one spelling source.

- `strings.rs::key` — GPUI `Keystroke::key` names (`KeyName` enum + derived `&str` consts) feed bindings, caret/effort navigation, interaction arrows, and PTY translation. Do not re-spell `"escape"`, `"home"`, `"left"`, etc.
- `strings.rs::keys` — JSON-RPC param keys; wire keys added here can be used directly in `json!({ CONST: value })`.
- `deeplinks.rs::Verb` — every link segment. `path`/`PaletteLink::verb`/`action_path` write the same constants the parsers match; a typo in one direction silently breaks `/go`. `SettingsTab::{as_str,from_name}` own tab spellings and aliases (no `tab_name()`/`settings_tab_for_name()`).
- `transcript::ArchivedPhase` (`commentary`/`final_answer`), `DiffFileKind::as_str()`, and `composer_controls::SlashCommandName` (shared with `cli_handoff` for `/cli`/`/desktop`) are the other typed sets.
- Deliberately NOT centralized: `activity_state_slug` ("done" is intentionally not `status::COMPLETED`), `tracker_status_label`, `TerminalPosition::id()` ("left"/"right" are settings identity, not keystrokes), theme-mode "light"/"dark". Frequency alone is not a reason to couple unrelated identities.
- Rust gotchas: `match` patterns need named/associated `const`s, not `const fn` calls; `format!` capture cannot use paths (`format!("{}/{}", Verb::CONFIG, path)`); guarded match arms still need a `_` arm for exhaustiveness.
