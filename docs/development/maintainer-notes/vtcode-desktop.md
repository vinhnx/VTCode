# vtcode-desktop maintainer notes

Detailed contracts and gotchas for `crates/codegen/vtcode-desktop/`, moved verbatim from its [AGENTS.md](../../../crates/codegen/vtcode-desktop/AGENTS.md). Read the section for the subsystem you are changing.

[Root AGENTS.md](../../../AGENTS.md) | macOS-only (Apple silicon) GPUI Kit (`=0.9.1`, `gpui-pre 0.3.12`) app; modules: `view/` (screens), `files/` (snapshot, fuzzy search, launch/mutate), `themes/` (tokens), `preferences/`, `transport.rs`, `localization/`, `app_icon.rs` (artwork + Dock).

## Hard rules

- WCAG AA 4.5:1 for foreground + every accent vs background in all themes (`every_theme_*` tests + `cargo nextest run -p vtcode-ui -E 'test(theme)'`); focus indicators get their own contrast check apart from text.
- All user-facing strings localized (`rust_i18n::t!`, 20 locales, args match `%{...}` placeholders); locale data lives per-surface in `locales/app.<ns>.yml` (one line per key, `_version: 2` first line, no trailing whitespace in values); GUI tests use `#[gpui_kit::test]` with stable `ElementId`s, `lock_scroll_axis()` before `.test_support()`, and `set_reduce_motion(true)` for overlay-click flows (opacity fades stay clickable).
- Every action keyboard-reachable with visible focus; overlays dismiss via `dismiss_overlay` paths and restore focus (`*_return_focus`), new overlays must also bind Escape on the topmost surface and be dropped when `open_settings`/`activate_composer` can mount another route beneath them; rail selections use `desktop_selected` on `secondary` surfaces; rails on a `popover` panel (e.g. the license viewer) use `secondary`; icon-only controls carry an accessible name (+ tooltip when scope needs explaining); never encode meaning by color alone; Buttons for in-app commands via tier builders (`desktop_primary_button` only for the default commitment, `desktop_default_button` for ordinary visible actions, `desktop_danger_button` for destructive, ghost for quiet/inline; `desktop_elevated` only on floating-layer composer decision actions — send + running trio share `composer_run_geometry`, gated on enabled since Kit replays instance shadow in its disabled arm) with result labels (`Delete`, `Cancel`) and `Delete "Name"?` native confirms (`[Destructive, Cancel]`, `matches!(answer.await, Ok(0))`, untestable headless); Full-access consent instead uses the in-app modal (`view/full_access_confirm.rs`, checkbox-gated Confirm + one-shot `fullAccessConfirmed` attestation, headless-tested); `Switch` for immediately-applied settings.

## Best practice

- Compose from `view/components.rs` (`desktop_button` + tier builders `desktop_default_button`/`desktop_primary_button`/`desktop_danger_button`/`desktop_elevated`, `desktop_folder_tab_bar`, `settings_row`, `settings_group_box`, `accessible_group_box`, `centered_empty_state`, `pane_divider`, `nav_group_header`, `card_border_style`, `track_focus`, shimmer labels, turn pending row, `severity_marker`/`loading_marker_row` severity/loading rows with test identity kept on the caller wrapper, `modal_scrim`, `consent_title_row`); same-kind overlay openers toggle via `toggle_palette_kind`/`toggle_settings` (second trigger closes); rem scale (`text_sm`, `gap_2`, `p_4`) and component `Size` APIs over `px()` (pixels only for hairlines, platform insets, hit-test tolerances, and fixed pane/region geometry); `truncate()` long/dynamic text; mono font only for code/ids/shortcuts/aligned numbers; load the `gpui-kit` (coding guides) and `gpui-kit-design-guides` (design guides) skills via `read_skill` before UI work, follow their review checklists, and check `docs/development/desktop-component-review.md` before introducing a component (Applied/Retained/Not-needed decisions stand).
- Icon sizes follow the desktop tier table (all rem-based, so they track the UI font setting 14–24, default 16): bare `Icon::new` matches surrounding text (titles, button labels); `.small()` (14px @ 16rem) for dense rows, markers, tabs, and palette leading slots; `.size_4()` (16px) for input prefixes and nav labels; `.size_6()` (24px) for empty-state and attachment media only; `Button.icon(..)` is Kit-owned (it re-sizes the icon to the button size — never override). Reuse `transcript_icon_slot` for fixed leading slots and `files_panel::file_tree_row_icon` for file rows; register non-default glyphs in `ExtraIcons` + `DESKTOP_ICONS` (`desktop/assets.rs`). `view/palette.rs` nears the 1000-line ceiling (949 before the file-path command): new palette helpers go in `view/palette/` submodules (see `icons.rs`).
- States visible and honest: distinct hover/focus/selected/disabled/loading; spinners in `muted_foreground`; shimmer labels only while genuinely loading (skeleton viewers were removed in favor of shimmer text); disable submission in flight; errors scoped near the action (`colors.danger`, `text_sm`); keep views free of service/runtime logic. Shimmer color is builder-owned: pass the semantic tone to `shimmer_label`/`loading_marker_row(_with_spinner)` and let it derive the resting/highlight pair (`themes::shimmer_resting` + palette foreground) and the reduced-motion full-tone fallback. Never set a shimmer's `.text_color()` at the call site or leave the band to Kit's default derivation.
- Thin response routers: method match arms delegate to `apply_*`/`fail_*` beside the feature's request builders; failed responses route through `view/backend_events/response_error.rs` (`handle_response_error`), which owns each method's failure surface (pane-level error, silent acknowledgement, or the generic banner); `fail_pending_navigation()` on async errors; confirm destructive service calls natively and enforce server-side (service validates, client guards).
- Performance: memoize projections per revision/epoch (transcript revision, config catalog epoch, inspector); page long lists (20 rows + `Show more (N remaining)`); virtualize measured rows; remeasure only on typography/theme changes; blocking work via `background_spawn`; no I/O or unbounded loops in render fns. List readers are unsettled before first layout (gate overlay visibility on `transcript_layout_settled`); `on_next_frame` never runs headless (scroll synchronously, assert exactly).
- Motion policy: every UI animation stays under 300ms and every enter/appear path rides an ease-out-shaped curve — fades consume `MotionTokens` (`duration_fast`/`duration_normal` + `easing_enter`) via `zen_fade_animation`, and streamed transcript chunks fade over `STREAMING_FADE_MS` (280ms, Kit's own streaming preset) with `Easing::EaseOut` and zero stagger; `shared_motion_tokens_stay_within_ui_animation_policy` + `streaming_markdown_fades_chunks_without_word_stagger` pin the ceiling and the curve shape, and `with_animation` renders the end state under reduced motion with no manual gate.
- Pending workspace navigation survives transient gate contention: a refused `SESSION_LOAD` send keeps `pending_navigation` armed while the gate is held and retries after the freeing response is fully handled, instead of failing the handoff (an in-flight permission restore used to win this race and silently drop CLI `/desktop` session links). Retries wait out an in-flight switch and an unlanded list (`session_list_received`); refusal with a free gate (running turn, retained draft) and terminal conditions (target gone, workspace mismatch, session missing from a landed list) still fail fast. Pinned by the `handoff_*` tests in `view/tests/session_link.rs`.
- Transcript human-projection policy: `TranscriptItem.output` always holds human text — every store routes through `output_sections::human_output_text`/`human_output_option`, which strip the `Structured output:` JSON envelope core appends for the LLM (only `spool_note` prose survives) and collapse blanks to `None`; renderers (`markdown::render_output_text`) never see raw JSON, so never add a JSON branch there. Row titles, detail lines, session labels, and harness visibility all delegate to `vtcode-commons::{tool_headlines, tool_intent}` (shared with the CLI since the dedupe; new `HarnessEventKind`s must pick a visibility side at compile time there, failures/blocks stay, unknown names take the `humanize_tool_name` fallback, multi-line commands preview to the first line like CLI compact rows). Only surface composition stays local: verb categories and `Ran {cmd}`/`Search code for {q}`/`Grep {p} in {path}`/`List files in {loc}`/`Fetch {url}` gist routing, `gist_keys`/`extra_gist_keys` title-consumed keys so details never echo the title, `ToolOutput` merging into any row its `call_id` names (orphans keep the standalone fallback), and single-line title collapse. Edit rows join per-call `+A −D` stats from their `{call_id}:changes` FileChange sibling (live path only; restored rows keep plain/generic titles). Pinned by `human_output_*`, `output_text_*`, `tool_output_merges_*`, `gist_*`, `edit_stats_*`, and `multi_line_*`/`completed_commands_*` tests here plus the commons suites.

- Soft edges are one knob: surfaces that used to paint full-strength `colors.border` (dialogs, cards, pills, dividers, code panels) now use `themes::soft_edge_color` — the `border` token at 0.55 opacity — so boundaries read as quiet hairlines in every theme; tune the opacity there, never per surface. Contrast-derived `themes::hairline()` is a separate recipe that stays wherever a border must clear a floor on its own fill (composer, change-summary cards, theme swatches, terminal preview chips) — do not swap the two. Keep `border`/`input` opaque for Kit inputs and keep focus rings and semantic (`danger`/`success`) borders at full strength for contrast. `soft_edge_is_the_single_translucent_border_tone` and `card_border_style_pins_a_1px_theme_border` pin the contract.

## Typography & accessibility

- Hierarchy via the `components.rs` label ladder — `content_page_title` (`text_2xl`), `panel_title` (`text_lg`), `section_label`/`group_box_title` (`text_base`), `row_title` (`text_sm`), `eyebrow_label`/`row_description` (`text_xs`) — with `text_sm` body and `text_xs` metadata; `muted_text` for secondary info, `aa_muted` captions-only; semibold marks structural labels and active/emphasis states, medium marks emphasized values, regular is prose; `label_ladder_keeps_every_tier_distinct` pins the ordering at small/default/large base fonts; verify roles/labels in the test tree (`role()`, `label()`); container aria labels need `role(Group)`; type scales with the user's text-size choice, so verify zoom at several base fonts (wrapping, truncation, pane minima, virtual-list measurement, focus-ring clearance) and keep longer translations from clipping or shifting sibling spines.
- Theme tokens only: no hex/`rgb()`/`hsla()` outside `themes/`; read `cx.theme()` by semantic role (`background`/`foreground`, `muted`, `primary`, `danger`/`warning`/`success` only for their meanings; `chart_*` for categorical segments); floors: secondary copy targets 6:1 where headroom allows, muted text holds 5.0 (AA 4.5 is the absolute floor), chrome 3:1 (`faded_chrome`, `label_foreground`, `tab_foreground`); fills take the weakest separating step with raised keeping a gap above resting while hover takes the strongest readable step; derive via `readable_semantic_color`, `readable_indicator_color`, `accessible_focus_color`, `filled_button_foreground`; verify light + dark, never assume fg/bg polarity; sRGB holds on Display P3 via macOS color management (wide-gamut authoring blocked on kit support; `every_theme_stays_within_srgb_gamut` guards it).
- Transcript paragraph contract (desktop owns style constants + column, Kit owns layout): 1.6 body leading (≥1.5 WCAG floor, asserted in `markdown.rs`), 1rem paragraph gaps, left-aligned ragged-right always — GPUI `TextAlign` has no justify variant, and full justification harms narrow-column readability, so there is no desktop justify path to add. Hanging list markers, heading tiers, quote rails, and syntax token colors are Kit defaults VT Code does not override (code font/size/background are set in `markdown.rs`). Column caps come from the Settings → Appearance → Layout "Chat width" preference: `Comfortable` (the default) is 768 normal / 680 zen, `Wide` is 1200, and `Full extend` uses an effectively unbounded `max_w` so the column fills the conversation area while sidebar/inspector stay flex siblings. The comfortable zen cap keeps its 2rem title-spine inset per side on assistant prose (~88/~77 chars at default size on a 0.5-advance proportional basis); normal fits ~80-col code, zen trades it for focus (see the `view/overlays.rs` const comments for the measured math). `content_width()` in `view/overlays.rs` is the single resolution point every cap consumer calls. Long tokens break mid-token and wrap instead of clipping, staying inside the column on prose, notice, tool-output, fenced-code, and wide-table surfaces, with accessible text intact (`unbreakable_text_stays_inside_transcript_bodies`, `assistant_prose_measure_follows_the_column_minus_title_inset`, `wide_tables_stay_inside_the_conversation_column`, all in `view/tests/transcript_readability.rs`).
- Deliberate CLI divergence on the same readability intent: the TUI justifies agent prose (`justify_wrapped_lines_in_place`, non-last single-span lines only, never code/lists/links/diffs) and separates paragraphs with one deduped blank row (`push_blank_line`); desktop keeps the rag and the rem gap because its renderer cannot justify. Do not "sync" either side toward the other's mechanics — sync the intent (one gap between paragraphs, hanging continuation indents, no stacked separators, unbreakable content stays in its surface).

## Gotchas

- Nav tracks cap three pinned icons per track: the rail keeps Home/New/History and the toolbar keeps Search/Zen; everything else goes through the data-driven `NavMenuAction` overflow builder in `view/navigation.rs` (`nav-overflow` for the rail, `header-overflow` for the toolbar). Overflow-only actions have no clickable element id, so tests either dispatch the corresponding view method (`toggle_settings`, `toggle_inspector`, `open_utilities`, `set_navigation_visible`) or open the overflow trigger and find items by index — Kit's popup items expose `label`/`aria_toggled` but NOT an a11y `disabled` flag, so disabled-state gates must be asserted on the view method (`new_thread_available`), not the menu item. `view/tests/nav_track.rs` pins the cap, item lists, and state labels.
- Menu-bar close/Cmd-W share `menu_bar::should_hide` (objc2 AppKit bindings); the status item uses the mono template icon (never theme/app-icon art), `menu_bar::dispatch_status_action` (show-first for window-bound actions), and `MenuBarAction::is_allowed` validation through the rendered tree, with labels rebuilt on locale change; cross-window refresh goes through `reload_views`; settings/browser/review embed in the content slot under the persistent toolbar (`route_page`; `RouteHistory` cursor drives Back/Forward with session history as fallback, Close truncates; transient palette/preview/editors layer above); route close/pop always focuses the composer (deterministic landing spot, kept after embedding); Up/Down alias Left/Right settings nav; shortcut capture suppresses bindings by omitting `DESKTOP`/`SETTINGS` key contexts while the pill holds focus (`capture_suppresses_bindings`); below 900px viewports the sidebar collapses to its rail on every route including workspace (`NARROW_PANEL_BREAKPOINT`, shared via `compact_viewport`) and settings stacks its nav; windowed-zen drag strip (`zen-drag-strip`, 40px `ZEN_DRAG_STRIP_HEIGHT`) owns window dragging (`app_owns_titlebar_drag` disables ALL native AppKit drag, so zen needs its own `start_window_move` region or the window cannot move) and the traffic-light clearance, titles align to the content spine (no horizontal dodge); headless `start_window_move` is unimplemented — guard native drag calls with `#[cfg(not(test))]` and drive later nav via dispatched actions; window min-size is 600x560 (`desktop_window_options`); config groups rail sits beside content at >=960px viewport and stacks above it below (arithmetic breakpoint, untested with users); Kit `Button::toggled` is a11y-only; `border`/`input` are soft visible outlines (Codex-style hairlines, never transparent) feeding cards, dividers, Tags, and Kit inputs — give `GroupBox` fills their outline via `content_style(card_border_style())`, since Kit offers no fill+border variant; Kit `Button` centers its built-in icon/label pair (inner content is `justify_center` + `size_full`), so `.justify_start()` cannot left-align entries — rails use a custom icon+label child with an explicit `accessibility_label` (config rail); storage search keywords are plain substrings; storage mutations refetch usage and review protects the current session; shortcuts persist on Save/import and reinstall live (NoAction shadows retire old chords); fixed composer/transcript key contexts (`VTCodeComposer`/`VTCodeTranscript` in `init_keybindings`) reuse Kit input actions for readline parity (undo-preserving) while configurable commands stay in `shortcuts.rs` (overrides colliding with `FIXED_RESERVED_CHORDS` are rejected — keep it in sync with the fixed table); Tab-stop lives on the `FocusHandle` (`.tab_stop(true)` at creation), element `.tab_stop(false)` only opts out, and `.test_support()` must precede `.track_focus()` or headless `focused()` panics; headless `press` does not deliver `ctrl-z` (drive Undo via `cmd-z` press or menu dispatch); transcript follows THREAD_ID ordering with role labels from `t!`; Reasoning items carrying a diagnostic payload project to collapsible severity notices (`TranscriptItem::diagnostic_notice` + `toggle_notice`, rendered by `view/transcript_notice.rs`), payload-less reasoning stays an assistant message, and session restore skips Reasoning rows (archive text owns history); Kit `Radio` owns its focus handle internally (no caller roving — Tab plus shortcuts instead; checked/disabled rows attach no click handler, so radio-card pickers need an explicit commit control) and owns no hover state (cards add their own `.hover()` refinement, gated on enabled + unchecked), and lays label plus children out in a content column right of the indicator (descriptions align under the label with no caller offset); Kit `Badge` is count/dot/icon only (text pills are `Tag`); icons outside Kit's 106-icon default bundle must join `ExtraIcons` + `DESKTOP_ICONS` (`desktop/assets.rs`) or they render blank with no headless failure (native-only symptom); folder TabBars via `desktop_folder_tab_bar` (medium, uncapped, named TopRight-anchored overflow dropdown in the suffix instead of Kit's unlabeled menu button): no per-tab custom ids (tests scope + index), no `.context_menu()` on `Tab` (menus live on a trigger child + the close button), tabs never shrink (explicit reveal on select/keyboard, scroll-then-click in tests via `click_thread_tab_close`), bar ids scope paths but register nothing observable (wrappers own lookup ids).
- `secondary` == `group_box`/`sidebar`/`muted` surface fill: selections on those surfaces use `desktop_selected` (the readable `button_active` fill plus `.selected()` and `.toggled()`); `secondary` itself would disappear. On a `popover` panel (license viewer), select with `secondary` + `.toggled(..)`.
- Session changes while a turn runs route through the running-confirm modal (`view/running_confirm.rs`): UI entries use `*_from_ui`, confirm arms the intent, the running→idle transition drains it; every `running = false` writer must drain or drop the armed wait, and armed/modal state clears in `reset_session_state` plus the Exited/LaunchFailed/disconnect arms.
- Native menus are startup-static (`menu_bar::init_native_menus`, relocated from `bootstrap.rs`): labels cannot track state (Enter/Exit Full Screen is one toggling item); menu actions dispatch through window-level `on_action` (About → `view/about.rs`, topmost modal in `dismiss_overlay`) or app-level handlers (OpenHelp). About always shows AppKit's standard panel: `desktop/build_info.rs` feeds its version/build stamp, `build.rs` stamps the commit (`VTCODE_DESKTOP_BUILD_VERSION`, which packaging also writes to `CFBundleVersion`), and the GitHub/acknowledgments credits come from `Credits.html` installed into `Contents/Resources` — keep the two in sync. Both in-app About surfaces (the fallback dialog and Settings → About) paint the shared monochrome V (`components::brand_mark`, the `vtcode-mono.svg` sprite tinted by `colors.foreground`) rather than the Dock art: the app icon is the Appearance picker's subject and a raster art tile in an identity card fights every theme, while one SVG sprite follows the palette and needs no per-mode asset. `brand_logo` (the color art) stays for `empty_state`'s Bot media only. File transfer is platform-bound: Finder drops arrive as `ExternalPaths` only (promise-only sources are refused by AppKit with the no-drop cursor — the bundle must never declare `NSIsTouchNative`, packaging refuses it, since it would disable the touch-to-mouse emulation); gate drop listeners at attachment time on workspace presence; drag-out via `.on_drag` + `.external_drag_payload::<T>` promotes to a native session at window exit (`files::external_drag_payload` maps paths — the headless platform records promotions but nothing public reaches tests, so test the mapping as a pure fn). `window.is_fullscreen()` is headlessly testable (flag flip); `zoom_window` is not (needs `#[cfg(not(test))]`).
- Cross-env handoff: the slash catalog is service-owned, so desktop-only `/cli` is appended and CLI-only `/desktop` (intercepted natively as an already-here notice — the service arm would spawn a second instance) is filtered in `localize_slash_catalog` (`view/cli_handoff.rs`); new `CommandSkillSpec`s auto-appear in the desktop popup via `visible_commands_for_desktop`, so every addition needs a native route or a documented fallthrough. External launches (editors/terminals) live in `files/launch.rs` behind the fixed-argv boundary; success paths are covered by launch-interception tests, never real spawns. CLI `/desktop` hands off via `--session`/`--workspace` argv parsed once in `main` (`desktop/startup.rs`, unknown args ignored for Finder `-psn`) or, when a bundle claims the scheme, a `vtcode://` URL delivered through `on_open_urls` into a queueing inbox (`UrlInbox`) and dispatched to the `MainWindow` global (weak view + window handle); same-workspace links load directly via the UI entry, cross-workspace links arm pending navigation. The thread loads through pending navigation, and the CLI handoff command is `terminal_command_for_session` (fork, single builder shared with Settings → Connections). Terminal.app auto-runs it via a `.command` script (`files/launch.rs`: fixed `open` argv, single-quoted, owner-only, failure echo instead of silent exit); other terminals copy+open until verified. The terminal is a `CliTerminal` preference (Settings → Connections). Session/load fails fast when another process holds the session (close-and-reload error, no zombie runtime).
- Handoff ownership is a **fork**, in both directions. The canonical event log is single-writer (an exclusive `flock` on `session.lock`), so the CLI cannot hand its live thread id to the app: the receiver would hit `SessionBusy`. `/desktop` therefore copies the live thread into a new archive (`vtcode_core::core::threads::fork_thread_for_handoff`, which preserves the source snapshot whole — `progress` carries the loaded skills and turn number, and `finalize` would drop it) and hands the fork over; the desktop -> CLI direction already forks for the same reason (`--fork-session`). The link is addressed to the **resolved bundle** (`open -a <bundle>`), not to whatever build claims the `vtcode:` scheme, so a running instance receives it instead of a second one starting. A handoff arrival raises a notice (`notifications::handoff_received`: system banner when the window is backgrounded, in-app toast when focused, gated by the master toggle) whose click opens the handed-off thread via `NotificationTarget::Thread`; the notice must not double-load, since the handoff already requested the thread.
- `InspectorTab::Plan` and `InspectorTab::Tasks` are conditional: Plan joins the rail only while a plan approval carries viewable markdown and Tasks joins only with tracker activity, so rail/keyboard/menu code must use `visible_inspector_tabs()` (never `ALL`); every interaction replacement/clear and every tracker snapshot clear must call `reset_hidden_inspector_tab_if_stranded()`.
- Tasks viewer state (`tracker_snapshot`) feeds from live `tracker.updated` events plus newest-checkpoint seeding at session load, and resets on session switch and disconnect; rows key on the dotted `index_path` (`task-row-{path}`) with depth-clamped indent, and the current pick is leaf-aware (in-progress over pending over blocked).
- Plan-edit holds the panel through the service ack (`interaction_edit_pending`): every `pending_interaction_response` mutation must maintain the flag, and a terminal `TurnStatus` for the same turn releases a stranded lock when no re-show follows (blocked/recovered turns keep it).
- Custom themes (`themes/custom.rs`, `view/appearance_themes.rs`) are desktop-only: they store the same seven `PaletteSeeds` as a built-in row and resolve through `apply_palette`, so ids are never in `cli_id_for` and must not sync to the CLI. Saving validates only name uniqueness/length and `foreground`/`background` contrast; accent and semantic seeds self-correct at apply time via `readable_indicator_color`/`readable_semantic_color`. The Appearance section is a collapsed disclosure (`theme_editor.expanded`, header button `custom-themes-toggle`): the body card, editor, and rows only mount when open, opening any editor unfolds it, folding closes the editor like Cancel (no invisible interior layer left for Back to consume), and view-driven tab selection away from Appearance folds it back — Kit's own sidebar clicks bypass `select_settings_tab`, so they leave the section as-is. Render through a `GroupBox` child, never the `title` slot: the slot always mounts the child column and pays one gap, so the folded section would be 12px taller than its header.
- New user-visible strings stay English literals unless full native-quality translations ship for every locale (partial keys break per-locale completeness tests); reuse existing keys where possible.
- Change-viewer selection is dual-mode: path-based `select_change` follows the newest patch per path, while transcript filename links, diff-card CTAs, and restored Activity rows use `select_change_from_item` to pin the exact patch of one change card (`selected_change_source`). Every writer that replaces or clears `selected_change` must clear or set the source in the same step (`show_change` owns both; session reset and refresh failures clear both), or refreshes silently swap the pinned historical patch for the newest one. Pinned by `selecting_change_item_uses_its_patch_for_same_path` plus the `edit_stats_rows` filename tests.
- History palette search is `HistoryScope`-aware (Everywhere/Project/Session, Ctrl+S cycles broad-to-narrow): Session scope reads the live thread while the service serves Everywhere/Project recents through `session/recent_prompts` (newest-first, `MAX_RECENT_PROMPTS`); scope labels, cycle order, and wire values live only in `vtcode-commons` `history_scope`.
- Headless observation matches the focus-trap id, not the div id beneath it (`focus_trap("license-viewer", …)` is what `try_find("license-viewer")` sees; the panel's own `.id("license-viewer-panel")` never registers): keep the trap id identical to the test id on trapped dialogs, or lookups silently miss a rendered dialog.
- Pointer route exits (dismiss buttons, the `route_page` gutter via `dismissable_route_page`, sidebar session rows) go through `request_panel_dismiss` (`view/overlays.rs`), which prompts natively (`window.prompt` + testable `discard_after_confirm`, mirroring the delete confirms) before dropping staged shortcut edits or a theme draft; a config write in flight pins everything, and interior layers unwind one step first (editor guarded, capture cancelled). Route panels stop inner mouse-downs so the gutter sees only background presses — never `on_mouse_down_out` on a route panel (it also fires for toolbar Back, turning Back into close-plus-history-jump). Programmatic exits (palette, deeplinks, new/close, zen, focus) stay sync: most are chain-first callers where a deferred close breaks the follow-up action, so only guard chain-last callers.
- Settings is the only full-width route: `dismissable_route_page_with_layout(..., RoutePageLayout::FullWidth)` drops `route_page`'s `px_6`/`max_w(1500)` so `settings-panel` spans the center gutter edge-to-edge, while browser/review keep the centered inset. The horizontal gutter disappears, so the bottom gutter (`pb_6`) is the pointer-dismiss area and the settings header has no duplicate close X (Escape, bottom gutter, and toolbar Back remain). Full-width geometry and the browser contrast are pinned by `settings_panel_spans_the_center_container_while_other_routes_stay_inset`.
- Zen chrome shares one right-anchored float: `render_navigation_buttons` builds Back/Forward once for both the normal toolbar and `render_zen_floating_chrome`, whose group is absolutely positioned against a `.relative()` main column with the toggle as trailing child (so arrows appearing never move it). Insets reproduce the docked slot (title bar `pr_3` + small toolbar `p_1` minus the pill border); `zen_floating_chrome_keeps_the_toggle_slot_and_exposes_navigation` guards that alignment. Note zen hides the navigation rail, which resizes the center column itself — a separate absolute-position change from chrome jumping within its container.
- Launch-at-login (`view/login_items.rs`, `objc2-service-management`): the OS owns the truth — launch reconciles the `launch_at_login` intent with `SMAppService` status (the user can flip the item in System Settings), `RequiresApproval` keeps the intent and shows the Settings shortcut instead of failing, and headless tests drive the `cx`-scoped stub via `test_override` (never process-global state, tests run parallel).
