# vtcode-desktop maintainer notes

Detailed contracts and gotchas for `crates/codegen/vtcode-desktop/`, moved verbatim from its [AGENTS.md](../../../crates/codegen/vtcode-desktop/AGENTS.md). Read the section for the subsystem you are changing.

[Root AGENTS.md](../../../AGENTS.md) | macOS-only (Apple silicon) GPUI Kit (`=0.8.1`) app; modules: `view/` (screens), `files/` (snapshot, fuzzy search, launch/mutate), `themes/` (tokens), `preferences/`, `transport.rs`, `localization/`, `app_icon.rs` (artwork + Dock).

## Hard rules

- WCAG AA 4.5:1 for foreground + every accent vs background in all themes (`every_theme_*` tests + `cargo nextest run -p vtcode-ui -E 'test(theme)'`); focus indicators get their own contrast check apart from text.
- All user-facing strings localized (`rust_i18n::t!`, 20 locales, args match `%{...}` placeholders); locale data lives per-surface in `locales/app.<ns>.yml` (one line per key, `_version: 2` first line, no trailing whitespace in values); GUI tests use `#[gpui_kit::test]` with stable `ElementId`s, `lock_scroll_axis()` before `.test_support()`, and `set_reduce_motion(true)` for overlay-click flows (opacity fades stay clickable).
- Every action keyboard-reachable with visible focus; overlays dismiss via `dismiss_overlay` paths and restore focus (`*_return_focus`), new overlays must also bind Escape on the topmost surface and be dropped when `open_settings`/`activate_composer` can mount another route beneath them; rail selections use `desktop_selected` on `secondary` surfaces; rails on a `popover` panel (e.g. the license viewer) use `secondary`; icon-only controls carry an accessible name (+ tooltip when scope needs explaining); never encode meaning by color alone; Buttons for in-app commands via tier builders (`desktop_primary_button` only for the default commitment, `desktop_default_button` for ordinary visible actions, `desktop_tertiary_button` for outline actions needing a clear boundary with less emphasis, `desktop_danger_button` for destructive, ghost for quiet/inline; `desktop_elevated` only on floating-layer composer decision actions — send + running trio share `composer_run_geometry`, gated on enabled since Kit replays instance shadow in its disabled arm) with result labels (`Delete`, `Cancel`) and `Delete "Name"?` native confirms (`[Destructive, Cancel]`, `matches!(answer.await, Ok(0))`, untestable headless); Full-access consent instead uses the in-app modal (`view/full_access_confirm.rs`, checkbox-gated Confirm + one-shot `fullAccessConfirmed` attestation, headless-tested); `Switch` for immediately-applied settings.

## Best practice

- Compose from `view/components.rs` (`desktop_button` + tier builders `desktop_default_button`/`desktop_tertiary_button`/`desktop_primary_button`/`desktop_danger_button`/`desktop_elevated`, `desktop_folder_tab_bar`, `settings_row`, `settings_group_box`, `accessible_group_box`, `centered_empty_state`, `pane_divider`, `nav_group_header`, `card_border_style`, `track_focus`, shimmer labels, turn pending row, `severity_marker`/`loading_marker_row` severity/loading rows with test identity kept on the caller wrapper, `modal_scrim`, `consent_title_row`); same-kind overlay openers toggle via `toggle_palette_kind`/`toggle_settings` (second trigger closes); rem scale (`text_sm`, `gap_2`, `p_4`) and component `Size` APIs over `px()` (pixels only for hairlines, platform insets, hit-test tolerances, and fixed pane/region geometry); `truncate()` long/dynamic text; mono font only for code/ids/shortcuts/aligned numbers; load the `gpui-kit` (coding guides) and `gpui-kit-design-guides` (design guides) skills via `read_skill` before UI work, follow their review checklists, and check `docs/development/desktop-component-review.md` before introducing a component (Applied/Retained/Not-needed decisions stand).
- Icon sizes follow the desktop tier table (all rem-based, so they track the UI font setting 14–24, default 16): bare `Icon::new` matches surrounding text (titles, button labels); `.small()` (14px @ 16rem) for dense rows, markers, tabs, and palette leading slots; `.size_4()` (16px) for input prefixes and nav labels; `.size_6()` (24px) for empty-state and attachment media only; `Button.icon(..)` is Kit-owned (it re-sizes the icon to the button size — never override). Reuse `transcript_icon_slot` for fixed leading slots and `files_panel::file_tree_row_icon` for file rows; register non-default glyphs in `ExtraIcons` + `DESKTOP_ICONS` (`desktop/assets.rs`). `view/palette.rs` sits at the 1000-line ceiling: new palette helpers go in `view/palette/` submodules (see `icons.rs`).
- States visible and honest: distinct hover/focus/selected/disabled/loading; spinners in `muted_foreground`; shimmer labels only while genuinely loading (skeleton viewers were removed in favor of shimmer text); disable submission in flight; errors scoped near the action (`colors.danger`, `text_sm`); keep views free of service/runtime logic. Shimmer color is builder-owned: pass the semantic tone to `shimmer_label`/`loading_marker_row(_with_spinner)` and let it derive the resting/highlight pair (`themes::shimmer_resting` + palette foreground) and the reduced-motion full-tone fallback. Never set a shimmer's `.text_color()` at the call site or leave the band to Kit's default derivation.
- Thin response routers: method match arms delegate to `apply_*`/`fail_*` beside the feature's request builders; `fail_pending_navigation()` on async errors; confirm destructive service calls natively and enforce server-side (service validates, client guards).
- Performance: memoize projections per revision/epoch (transcript revision, config catalog epoch, inspector); page long lists (20 rows + `Show more (N remaining)`); virtualize measured rows; remeasure only on typography/theme changes; blocking work via `background_spawn`; no I/O or unbounded loops in render fns. List readers are unsettled before first layout (gate overlay visibility on `transcript_layout_settled`); `on_next_frame` never runs headless (scroll synchronously, assert exactly).
- Motion policy: every UI animation stays under 300ms and every enter/appear path rides an ease-out-shaped curve — fades consume `MotionTokens` (`duration_fast`/`duration_normal` + `easing_enter`) via `zen_fade_animation`, and streamed transcript chunks fade over `STREAMING_FADE_MS` (280ms, Kit's own streaming preset) with `Easing::EaseOut` and zero stagger; `shared_motion_tokens_stay_within_ui_animation_policy` + `streaming_markdown_fades_chunks_without_word_stagger` pin the ceiling and the curve shape, and `with_animation` renders the end state under reduced motion with no manual gate.
- Pending workspace navigation survives transient gate contention: a refused `SESSION_LOAD` send keeps `pending_navigation` armed while the gate is held and retries after the freeing response is fully handled, instead of failing the handoff (an in-flight permission restore used to win this race and silently drop CLI `/desktop` session links). Retries wait out an in-flight switch and an unlanded list (`session_list_received`); refusal with a free gate (running turn, retained draft) and terminal conditions (target gone, workspace mismatch, session missing from a landed list) still fail fast. Pinned by the `handoff_*` tests in `view/tests/session_link.rs`.

## Typography & accessibility

- Hierarchy via `row_title`/`row_description`, `text_sm` body, `text_xs` metadata; `muted_text` for secondary info, `aa_muted` captions-only; semibold reserved for unread/active/emphasis; verify roles/labels in the test tree (`role()`, `label()`); container aria labels need `role(Group)`; type scales with the user's text-size choice, so verify zoom at several base fonts (wrapping, truncation, pane minima, virtual-list measurement, focus-ring clearance) and keep longer translations from clipping or shifting sibling spines.
- Theme tokens only: no hex/`rgb()`/`hsla()` outside `themes/`; read `cx.theme()` by semantic role (`background`/`foreground`, `muted`, `primary`, `danger`/`warning`/`success` only for their meanings; `chart_*` for categorical segments); floors: secondary copy targets 6:1 where headroom allows, muted text holds 5.0 (AA 4.5 is the absolute floor), chrome 3:1 (`faded_chrome`, `label_foreground`, `tab_foreground`); fills take the weakest separating step with raised keeping a gap above resting while hover takes the strongest readable step; derive via `readable_semantic_color`, `readable_indicator_color`, `accessible_focus_color`, `filled_button_foreground`; verify light + dark, never assume fg/bg polarity; sRGB holds on Display P3 via macOS color management (wide-gamut authoring blocked on kit support; `every_theme_stays_within_srgb_gamut` guards it).

## Gotchas

- Menu-bar close/Cmd-W share `menu_bar::should_hide` (objc2 AppKit bindings); the status item uses the mono template icon (never theme/app-icon art), `menu_bar::dispatch_status_action` (show-first for window-bound actions), and `MenuBarAction::is_allowed` validation through the rendered tree, with labels rebuilt on locale change; cross-window refresh goes through `reload_views`; settings/browser/review embed in the content slot under the persistent toolbar (`route_page`; `RouteHistory` cursor drives Back/Forward with session history as fallback, Close truncates; transient palette/preview/editors layer above); route close/pop always focuses the composer (deterministic landing spot, kept after embedding); Up/Down alias Left/Right settings nav; shortcut capture suppresses bindings by omitting `DESKTOP`/`SETTINGS` key contexts while the pill holds focus (`capture_suppresses_bindings`); below 900px viewports the sidebar collapses to its rail on every route including workspace (`NARROW_PANEL_BREAKPOINT`, shared via `compact_viewport`) and settings stacks its nav; windowed-zen drag strip (`zen-drag-strip`, 40px `ZEN_DRAG_STRIP_HEIGHT`) owns window dragging (`app_owns_titlebar_drag` disables ALL native AppKit drag, so zen needs its own `start_window_move` region or the window cannot move) and the traffic-light clearance, titles align to the content spine (no horizontal dodge); headless `start_window_move` is unimplemented — guard native drag calls with `#[cfg(not(test))]` and drive later nav via dispatched actions; window min-size is 600x560 (`desktop_window_options`); config groups rail sits beside content at >=960px viewport and stacks above it below (arithmetic breakpoint, untested with users); Kit `Button::toggled` is a11y-only; `border`/`input` are soft visible outlines (Codex-style hairlines, never transparent) feeding cards, dividers, Tags, and Kit inputs — give `GroupBox` fills their outline via `content_style(card_border_style())`, since Kit offers no fill+border variant; Kit `Button` centers its built-in icon/label pair (inner content is `justify_center` + `size_full`), so `.justify_start()` cannot left-align entries — rails use a custom icon+label child with an explicit `accessibility_label` (config rail); storage search keywords are plain substrings; storage mutations refetch usage and review protects the current session; shortcuts persist on Save/import and reinstall live (NoAction shadows retire old chords); fixed composer/transcript key contexts (`VTCodeComposer`/`VTCodeTranscript` in `init_keybindings`) reuse Kit input actions for readline parity (undo-preserving) while configurable commands stay in `shortcuts.rs` (overrides colliding with `FIXED_RESERVED_CHORDS` are rejected — keep it in sync with the fixed table); Tab-stop lives on the `FocusHandle` (`.tab_stop(true)` at creation), element `.tab_stop(false)` only opts out, and `.test_support()` must precede `.track_focus()` or headless `focused()` panics; headless `press` does not deliver `ctrl-z` (drive Undo via `cmd-z` press or menu dispatch); transcript follows THREAD_ID ordering with role labels from `t!`; Reasoning items carrying a diagnostic payload project to collapsible severity notices (`TranscriptItem::diagnostic_notice` + `toggle_notice`, rendered by `view/transcript_notice.rs`), payload-less reasoning stays an assistant message, and session restore skips Reasoning rows (archive text owns history); Kit `Radio` owns its focus handle internally (no caller roving — Tab plus shortcuts instead; checked/disabled rows attach no click handler, so radio-card pickers need an explicit commit control) and owns no hover state (cards add their own `.hover()` refinement, gated on enabled + unchecked), and lays label plus children out in a content column right of the indicator (descriptions align under the label with no caller offset); Kit `Badge` is count/dot/icon only (text pills are `Tag`); icons outside Kit's 106-icon default bundle must join `ExtraIcons` + `DESKTOP_ICONS` (`desktop/assets.rs`) or they render blank with no headless failure (native-only symptom); folder TabBars via `desktop_folder_tab_bar` (medium, uncapped, named TopRight-anchored overflow dropdown in the suffix instead of Kit's unlabeled menu button): no per-tab custom ids (tests scope + index), no `.context_menu()` on `Tab` (menus live on a trigger child + the close button), tabs never shrink (explicit reveal on select/keyboard, scroll-then-click in tests via `click_thread_tab_close`), bar ids scope paths but register nothing observable (wrappers own lookup ids).
- `secondary` == `group_box`/`sidebar`/`muted` surface fill: selections on those surfaces use `desktop_selected` (the readable `button_active` fill plus `.selected()` and `.toggled()`); `secondary` itself would disappear. On a `popover` panel (license viewer), select with `secondary` + `.toggled(..)`.
- Session changes while a turn runs route through the running-confirm modal (`view/running_confirm.rs`): UI entries use `*_from_ui`, confirm arms the intent, the running→idle transition drains it; every `running = false` writer must drain or drop the armed wait, and armed/modal state clears in `reset_session_state` plus the Exited/LaunchFailed/disconnect arms.
- Native menus are startup-static (`menu_bar::init_native_menus`, relocated from `bootstrap.rs`): labels cannot track state (Enter/Exit Full Screen is one toggling item); menu actions dispatch through window-level `on_action` (About → `view/about.rs`, topmost modal in `dismiss_overlay`) or app-level handlers (OpenHelp). About always shows AppKit's standard panel: `desktop/build_info.rs` feeds its version/build stamp, `build.rs` stamps the commit (`VTCODE_DESKTOP_BUILD_VERSION`, which packaging also writes to `CFBundleVersion`), and the GitHub/acknowledgments credits come from `Credits.html` installed into `Contents/Resources` — keep the two in sync. File transfer is platform-bound: Finder drops arrive as `ExternalPaths` only (promise-only sources are refused by AppKit with the no-drop cursor — the bundle must never declare `NSIsTouchNative`, packaging refuses it, since it would disable the touch-to-mouse emulation); gate drop listeners at attachment time on workspace presence; drag-out via `.on_drag` + `.external_drag_payload::<T>` promotes to a native session at window exit (`files::external_drag_payload` maps paths — the headless platform records promotions but nothing public reaches tests, so test the mapping as a pure fn). `window.is_fullscreen()` is headlessly testable (flag flip); `zoom_window` is not (needs `#[cfg(not(test))]`).
- Cross-env handoff: the slash catalog is service-owned, so desktop-only `/cli` is appended and CLI-only `/desktop` (intercepted natively as an already-here notice — the service arm would spawn a second instance) is filtered in `localize_slash_catalog` (`view/cli_handoff.rs`); new `CommandSkillSpec`s auto-appear in the desktop popup via `visible_commands_for_desktop`, so every addition needs a native route or a documented fallthrough. External launches (editors/terminals) live in `files/launch.rs` behind the fixed-argv boundary; success paths are covered by launch-interception tests, never real spawns. CLI `/desktop` hands off via `--session`/`--workspace` argv parsed once in `main` (`desktop/startup.rs`, unknown args ignored for Finder `-psn`) or, when a bundle claims the scheme, a `vtcode://` URL delivered through `on_open_urls` into a queueing inbox (`UrlInbox`) and dispatched to the `MainWindow` global (weak view + window handle); same-workspace links load directly via the UI entry, cross-workspace links arm pending navigation. The thread loads through pending navigation, and the CLI handoff command is `terminal_command_for_session` (fork, single builder shared with Settings → Connections). Terminal.app auto-runs it via a `.command` script (`files/launch.rs`: fixed `open` argv, single-quoted, owner-only, failure echo instead of silent exit); other terminals copy+open until verified. The terminal is a `CliTerminal` preference (Settings → Connections). Session/load fails fast when another process holds the session (close-and-reload error, no zombie runtime).
- `InspectorTab::Plan` and `InspectorTab::Tasks` are conditional: Plan joins the rail only while a plan approval carries viewable markdown and Tasks joins only with tracker activity, so rail/keyboard/menu code must use `visible_inspector_tabs()` (never `ALL`); every interaction replacement/clear and every tracker snapshot clear must call `reset_hidden_inspector_tab_if_stranded()`.
- Tasks viewer state (`tracker_snapshot`) feeds from live `tracker.updated` events plus newest-checkpoint seeding at session load, and resets on session switch and disconnect; rows key on the dotted `index_path` (`task-row-{path}`) with depth-clamped indent, and the current pick is leaf-aware (in-progress over pending over blocked).
- Plan-edit holds the panel through the service ack (`interaction_edit_pending`): every `pending_interaction_response` mutation must maintain the flag, and a terminal `TurnStatus` for the same turn releases a stranded lock when no re-show follows (blocked/recovered turns keep it).
- Custom themes (`themes/custom.rs`, `view/appearance_themes.rs`) are desktop-only: they store the same seven `PaletteSeeds` as a built-in row and resolve through `apply_palette`, so ids are never in `cli_id_for` and must not sync to the CLI. Saving validates only name uniqueness/length and `foreground`/`background` contrast; accent and semantic seeds self-correct at apply time via `readable_indicator_color`/`readable_semantic_color`.
- New user-visible strings stay English literals unless full native-quality translations ship for every locale (partial keys break per-locale completeness tests); reuse existing keys where possible.
- History palette search is `HistoryScope`-aware (Everywhere/Project/Session, Ctrl+S cycles broad-to-narrow): Session scope reads the live thread while the service serves Everywhere/Project recents through `session/recent_prompts` (newest-first, `MAX_RECENT_PROMPTS`); scope labels, cycle order, and wire values live only in `vtcode-commons` `history_scope`.
- Headless observation matches the focus-trap id, not the div id beneath it (`focus_trap("license-viewer", …)` is what `try_find("license-viewer")` sees; the panel's own `.id("license-viewer-panel")` never registers): keep the trap id identical to the test id on trapped dialogs, or lookups silently miss a rendered dialog.
- Pointer route exits (dismiss buttons, the `route_page` gutter via `dismissable_route_page`, sidebar session rows) go through `request_panel_dismiss` (`view/overlays.rs`), which prompts natively (`window.prompt` + testable `discard_after_confirm`, mirroring the delete confirms) before dropping staged shortcut edits or a theme draft; a config write in flight pins everything, and interior layers unwind one step first (editor guarded, capture cancelled). Route panels stop inner mouse-downs so the gutter sees only background presses — never `on_mouse_down_out` on a route panel (it also fires for toolbar Back, turning Back into close-plus-history-jump). Programmatic exits (palette, deeplinks, new/close, zen, focus) stay sync: most are chain-first callers where a deferred close breaks the follow-up action, so only guard chain-last callers.
- Launch-at-login (`view/login_items.rs`, `objc2-service-management`): the OS owns the truth — launch reconciles the `launch_at_login` intent with `SMAppService` status (the user can flip the item in System Settings), `RequiresApproval` keeps the intent and shows the Settings shortcut instead of failing, and headless tests drive the `cx`-scoped stub via `test_override` (never process-global state, tests run parallel).
- New scrim modals ship five things together: a `dismiss_overlay` arm in topmost-first order, return-focus capture at open with a composer fallback at close, `.focus_trap(<dialog-id>, &focus)` right after `.track_focus()`, an Escape test (dismiss + restore + no side effects), and a Tab-wrap test via `assert_tab_trapped_within_dialog` (`view/tests/mod.rs`); route panels stay deliberately untrapped (`tab_out_and_back_into_scope`).
- Title-bar budgets follow the main column, never the viewport: the bar lives beside the navigation, so viewport fit alone lets buttons hide under the sidebar — assert against `pane-root`, which stretches to main. The workspace suffix plus speed tag collapse below 760px of main (`MAIN_COLUMN_DETAILS_BREAKPOINT`, suffix capped at `WORKSPACE_LABEL_MAX_WIDTH`); the footprint math lives in the `view.rs` const comment and the chrome computation must mirror root layout's expanded predicate exactly.
- Kit `Editor` has a fixed intrinsic height (`auto_grow`/`set_rows` are textarea-only), so size it explicitly: the markdown preview derives `.h()` from the document line count clamped to 3–24 rows at `mono_font_size * 1.5` (mirrors kit-private `EDITOR_LINE_HEIGHT`). Read-only editors propagate Tab instead of indenting, so they join trap cycles as interior stops — assert via the state `focus_handle`, since `Editor` has no `.id()`.
- `.test_support()` wraps the element in `Observed`, which does not forward div-only builders: `lock_scroll_axis` after it fails to compile, so call `.test_support()` after div-specific builders (it must still precede `.track_focus()`), and plain `.id()` divs never register for `find()`/`try_find()` without it.
- Pin Tab-wrap with `assert_tab_trapped_within_dialog` when both endpoints carry app ids; when interior stops carry kit-owned ids (palette input, picker tabs, closed `Select` — which adds an id-less stop between save and the select), pin `contains_focused` per press in both directions plus a visited-set assertion instead.
- `EditorState::set_value` suppresses `InputEvent::Change`, so dirty-tracking subscriptions only fire on real edits — tests must type honest keystrokes via `window.input`, never seed the draft with `set_value`.
- `files_panel.rs` sits at 950 lines after its preview-save split: `view/file_preview.rs` owns the save flow and source-viewport sizing, so extend that module instead of growing the panel; new fixed chords join `FIXED_RESERVED_CHORDS` in the same edit or configurable rebinding silently shadows (the `secondary-s` test chord had to move to `secondary-y` when Cmd+S became the fixed preview save).
- Settings hosts Kit `Settings` on wide viewports (`view/settings_kit.rs`, one Element item per page built from `SettingsTab::ALL` with an exhaustive match so tab reorder/add cannot desync Kit order from the selection index, config stays last; narrow keeps the legacy stacked nav/content): pane renderers are props-and-handle content builders (`*Props::capture(&DesktopView)` plus `(props, view, cx)` associated fns — never read the rendering entity inside its own render, and `AnyElement` is single-use so Kit items rebuild from cloned props per render); `cx.theme()` borrows `cx`, so builders that also take `cx` mutably must clone an owned `Theme` first or reorder theme reads last; the 8-page remount id `settings-kit-{page_ix}` pushes view selection into Kit one-way (Kit-internal sidebar clicks never sync back until upstream on-select — WebMCP side effects stay on the view-driven path; the storage summary additionally fetches on display from its Kit item closure because Kit clicks bypass view selection); panel-level settings actions run only from the panel root and must `cx.propagate()` otherwise, because matched keymap actions stop propagation by default and would otherwise swallow control keys (sliders, inputs, capture pill); headless scrolls must anchor on a visible element (`settings-panel` center sits over Kit's content list — never the below-fold target, since test scrolls dispatch at the anchor, and never the `settings-kit-N` id, which is a Kit state scope, not an element); Kit sidebar rows are click-only with no accessible label in 0.8.1 (tab-cycle actions plus the fuzzy palette are the keyboard path).
