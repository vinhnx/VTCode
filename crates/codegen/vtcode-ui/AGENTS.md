# vtcode-ui

[Root AGENTS.md](../../../AGENTS.md) | Unified UI: design system, theme registry, TUI framework. Consolidated from `vtcode-design` and `vtcode-theme`.

## Modules

| Area | Path |
| --- | --- |
| Design system | `design/` — color conversion, style bridging, layout, diff, panel primitives |
| Theme registry | `theme/` — ThemeStyles, runtime state, syntax theme resolution |
| TUI framework | `tui/` — session, widgets, runner, markdown rendering, config |

## Rules

- `UpdateProgress` is presentation-only: reject stale operation IDs, deduplicate against the displayed phase, exclude the transient row from history/exports/selection even when the transcript body is empty, and use shared shimmer/accessibility ticks without reflow. Show its footer fallback only when the current frame has no progress row, including progress-only transcript allocations; reset that geometry each frame. Keep configured footer text via SetConfiguredInputStatus while the row is visible; runtime SetInputStatus/ActivityState updates must not replace it. Retain arbitrary custom-command output by source, and clear it only on a configured empty/None update. Recognize the existing labelled/compact Git formats before matching activity words in branch names. Observe feedback once after overlays, including the footer fallback; covered or ellipsis-only surfaces do not count. Scoped phases use `InlineHandle::replace_progress_phase` and restore only their original operation; probe activity belongs to `UpdateProgress`, since runtime input status is hidden by the active row. Runtime guards own accepted operations; keyboard/paste handlers must not invent unowned progress. Guards transfer ownership at turn handoff; see [response progress](../../../docs/development/response-progress.md). `InlineHandle::review_evidence` records a capture then focuses Transcript Review; its boolean reports channel acceptance. Alt+click evidence uses the review body's wrapped rows and scroll position; ordinary selection stays overlay-owned. Keep evidence navigation independent of prompts, command execution, and transcript geometry.

- `design` and `theme` are re-exported at crate root (`pub use design::*; pub use theme::*`) for backward compatibility with the old standalone crates. `publish = false` — internal crate, not published to crates.io. `tui/core_tui/types/{message_commands,control_commands}.rs` own shared text-command definitions and stateless handle forwarding through private macros; preserve struct-variant syntax and keep app-only state local (see [message protocols](../../../docs/development/ui-message-protocol.md)). `tui/core_tui/` owns the full terminal session lifecycle; `session/action.rs` owns rebindable action dispatch, including Ctrl+B `BackgroundOperation`; `session/sticky_prompt.rs` resolves sticky user ownership/layout and shares navigation across mouse paths; `transcript_area` is its body rectangle (header excluded). `session/layout_state.rs` owns rendered hit areas and `session/render_state.rs` owns redraw/full-clear scheduling. `session/modal/render/` splits modal painting: `mod.rs` body dispatch, `wizard.rs` tabs/steps/body, `list_item.rs` rows, `instructions.rs` instruction blocks, `inputs.rs` search/secure prompts. `session/events/` splits app key handling: `mod.rs` keeps the `process_key_with_clipboard_readers` dispatcher and entry points, `paste.rs` clipboard, `secure_prompt.rs` masked input, `modal_keys.rs` modal/mode-switch gating, `viewer.rs` review/diff-preview routing, `submit.rs` tab-queue/submit, `history.rs` history picker, `emit.rs` event emission. `session/tool_output_viewer/` (dir `transcript_review/`) splits review state: `mod.rs` types plus viewer render entry points, `state.rs` open/refresh lifecycle, `scroll.rs` scrolling, `search.rs` in-place search, `render.rs` hit-testing/export impl, `sources.rs` source collection. `tui/core_tui/app/session/task_panel.rs` retains compact TODO-panel wrapping/height/header helpers; `tui/ui/` has reusable widgets (Markdown, interactive list). Fuzzy matching primitives (`normalize_query`, `FuzzyQuery`) live in `vtcode-commons::search` and are re-exported through `tui/ui/search.rs`, which only adds the UI-only `ListSearchFilter`/`SearchCandidate`/`exact_terms_match`; do not fork the matcher here. Markdown tables use Codex-style padded horizontal separators, width-aware column shrinking, and aligned key/value records when a grid becomes unreadable, so callers must pass content width after transcript framing. Bridge prompts use the bounded deferred-event queue while transient overlays own input; keep them prompt-only so slash-command parsing remains terminal-only. The `@` file palette (`session/file_palette/`) keeps all filesystem metadata off the render path: the binary's `DirLister` returns `DirEntryInfo` (kind, symlink target, broken flag) captured once per listing, `FileKind::classify` is pure, and rows render a kind glyph plus `→ target` for symlinks; ignore filtering is the walker's job, never a UI-side skip list. `tui/config/constants/` holds TUI-specific defaults — keep them here, not in `vtcode-config`; identical shared config defaults are re-exported through existing TUI paths; snapshot tests live in `tui/core_tui/widgets/snapshots/`.

## Gotchas

- Style bridging is centralized in `design/color.rs` + `design/style.rs` (crate-internal); downstream code uses the `tui/core_tui/style.rs` wrappers — do not fork new converters. The `crossterm` dependency enables `event-stream` and `osc52` features; do not duplicate these in downstream crates. It is a maintained fork at `patches/crossterm` (root `[patch.crates-io]`) that adds `Event::ColorSchemeReport` for the Contour `CSI ? 997`/`2031` dark-light extension — re-apply that patch when upgrading crossterm, and treat the fork as workspace code for `-D warnings`. Gate the fork-only atomic `read_timeout` with `vendored_crossterm`; registry terminal drains use bounded polling without a subsequent blocking read. Fork drains are bounded by time and event count; reserve persistent footer regions before truncating activity or hints. Modal painting must check `has_active_overlay()` before clearing the frame; without an overlay, clear only stale modal hit areas. Cover base transcript/input/status and Escape restoration through full-session wide/narrow render tests. Standalone and core session defaults are inline; callers that need alternate-screen rendering must opt in explicitly. `MouseSelectionState` retains transcript/overlay ownership after mouse-up; transcript scrolling, sticky body adjustments, and body clipping apply only to transcript selections. Floating approval/list overlays own mouse input only inside `modal_list_area`; wheel events outside that hitbox must pass through to the transcript so long plan markdown remains scrollable. Floating overlays reuse one bottom-half rectangle for popup rendering and transcript clipping; keep `transcript_area` as the source of truth for scroll metrics and hit-testing, and do not pass an explicit transcript rectangle to `apply_view_rows` as if it were the full viewport before rendering (that breaks scroll-anchor restoration). Modal list hit-testing must go through `modal::visible_index_at_row` with the same `footer_hint`/inline-editor inputs render used, or clicks drift by the summary/editor rows. `ActivityState` is the authoritative busy/idle signal even without animation. `Blocked` is quiescent despite its status text, so it must not trigger spinners or slash-command blocking; keep Building/Recovery mode boundaries intact. `/model` steers to the active turn while running (both input paths, including Tab/Ctrl+Enter/Ctrl+M drafts) instead of queueing; other slash commands keep existing busy rules. Derive `InputOwner` from overlay/activity state; activity changes update modal restore flags. Transcript cache validity is explicit, not revision zero. Tick sends coalesce, but input and PTY bytes stay ordered.
- Screen-reader mode opens Transcript Review in raw mode; live enablement uses its idempotent mode setter to invalidate mode-dependent search caches and clamp scrolling. Composer Shift/Alt+Enter follows overlay ownership but precedes submit-only commands; modified Enter preserves trailing backslashes. The shared active-PTY counter is also a global loading observer; compact PTY rendering may hide live rows, so keep its footer status fallback in `session/state.rs`. Background activity (managed subagents, background subprocesses, retained exec sessions) is a second global loading observer: it drives the input-status shimmer and animation tick rate but must never set `is_running_activity` (turn-busy guards stay turn-scoped). It surfaces idle-only through `background_activity_status_text` in the input status line (never `status_left_text`); while `progress` owns the transcript loading row it moves to a static `· N bg` suffix there plus a short `• N bg` / `✓ N done` header badge, so the bottom line never blinks. Bottom-line background hints (drawer and foreground-PTY `Ctrl+B background`) are suppressed while anything is busy (`progress` active, foreground PTY live, or turn running) so the composer line never reflows as phases or the PTY counter toggle; while busy the `Ctrl+B` entry point rides the transcript loading row as a static rebound-aware suffix plus the header suggestions line (`Ctrl+B`/`Alt+S`/`/jobs`/empty-Enter keep working).
- PTY/tool reflow must preserve explicit status color on the `•` prefix; apply action/tool styling only to the verb so success, failure, and warning remain visually distinct; fullscreen `Ctrl+T` opens ordered session-local Transcript Review (rich/raw via `r`) but remains text transpose outside fullscreen, and complete PTY captures stay behind bounded live lines. Compact review hints are the only normal-transcript open target; derive their label from the primary binding and rebuild their hit regions after transcript reflow.
- Tool and PTY blocks reserve at least one blank line above and below, including directly after agent prose so the message stays visually distinct from its work log; shell syntax highlighting is accepted only when it produces distinct token colors, otherwise semantic token styles are the fallback. Diff rendering uses a soft add/delete row tint plus stronger intraline chips across modal preview, markdown, reflow, and ANSI output; full-width tint detection keys off the actual row marker and uncoloured side-by-side divider, never a later `+`/`-`-prefixed word chip; file and hunk section headers are bold foreground-only metadata, ANSI16 and no-color remain foreground-only, responsive diff layout measures post-frame content width, hides the visible gutter when source room is tight, and falls back from side-by-side below the shared threshold; overlays cache one `vtcode_diff::DiffDocument` at open time and only relayout or scroll it. Inline TUI diff bodies word-wrap via transcript reflow (no ellipsis under the safety cap); expandable `review full diff` + `DiffReviewAnchor` only when the complete unified body is still held (never registry excerpts); compact tinted rows hang under the marker cell; activation takes the matching anchor without cloning unified content; the review overlay stays full-viewport, paints and counts remaining rows from one `layout_display_lines` pass, and does not claim full-diff expand from truncated previews.
- Task-panel tree rows use the shared hanging-prefix wrapper in `session/text_utils.rs`; keep panel row heights derived from wrapped content so long titles wrap cleanly in the docked panel (compact transcript shows header plus the accented current `▶` row, expanded shows header+truncated tree; both surfaces style status through text only — done struck-through/italic/dimmed, current bold `primary`, blocked `warning` — via the shared style bridge, never forked converters). `toggle_tool_display_mode` is a rebindable session action (default `Alt+T`); dispatch it before the legacy `Alt+T` text-edit shortcut and invalidate transcript caches after toggling. Info/Warning/Error transcript groups (plain colored lines, no borders) must invalidate from their first line when a member changes or is appended, because later lines affect the cached group head; each Info tool-summary line is a boundary, not part of the group. Error uses the `error` token, Warning uses the dedicated amber `warning` token (scheme-picked bright/dark amber, never the brand `logo_accent`), Info uses dimmed foreground.
- Panic-hook terminal mutation tracking is set only after a successful terminal mutation, so partial TUI setup errors do not emit restore sequences. Alternate-screen teardown clears the alternate viewport before leaving it, and render/finalize writes must use the shared terminal-operation lock so no final frame reaches the main scrollback after restoration is claimed. Reasoning summaries use the dimmed italic style and arrive only through the provider-classified normalized stream; raw or continuation-only reasoning stays hidden. `benches/transcript.rs` measures render/events through existing app entrypoints; scroll/selection cases must assert that their events change the rendered frame. `core_tui/program_status` owns opt-in session records, successful-write caching, and cleanup under the terminal-operation lock. Project children only while enabled; live enabling uses the existing Local Agents snapshot, and disabled flushes must still retry owned clears. Projection commands never change input authority. See [guide](../../../docs/development/terminal-program-status.md).
