## Architecture Notes

- **Canonical home** for all provider code. Core's `llm/` is a thin re-export layer + factory/CGP. Merge Gateway defaults to native `/v1/responses`; an explicit `/v1/openai` base selects legacy Chat Completions. Native snapshots are normalized into incremental deltas after the first cumulative frame is confirmed, while the initial snapshot remains buffered so `fallback_restart` can discard stale pre-output state. Reasoning is route-specific: forward `reasoning_effort` only for routes advertising that control and `thinking.budget_tokens` (clamped below `max_tokens`) for thinking-budget routes, never a generic provider-wide field; persisted effort settings are omitted on an unsupported active route during normal request assembly, while explicit capability resolution remains strict; normalized reasoning must classify provider-confirmed summaries separately from raw or continuation-only details, exposing only summaries to UI while preserving continuation metadata; preserve provider `ReasoningStage` events when converting to normalized streams so the core runtime lifecycle can render them. Collapsed-output notices use one typed `MessageClearAt` marker after tool-result user messages; only provider/model routes advertising native support use the required beta and `clear_at`, while all other builders translate the marker to ordinary system/history instructions without sending `clear_at`. `ModelResolver::resolve_with_mode` and `availability_with_mode` must receive the loaded config's credential storage mode; compatibility wrappers are only for callers without workspace config. Provider compaction outputs are canonical replay windows: preserve opaque compaction blocks and aggregate per-iteration usage. `ResolvedModel.api_key_env` carries provider-override credential identity through availability and picker selection; do not infer availability from provider alone. `system_prompt.rs` provides stub getters with `OnceLock` setters; vtcode-core overrides at init. The runloop's stream-timeout retry falls back to non-streaming keyed on `supports_non_streaming`; a provider that services non-streaming generation must override it explicitly (see `MergeGatewayProvider`) — relying on the trait default lets the fallback silently regress.

## Coding Conventions

Independent `generate_auxiliary` calls use HTTP without leasing the primary WebSocket or changing its continuation; wrappers must forward the override. Responses WebSocket generation and both streaming APIs share one leased socket lane; restore only after validated completion is delivered, not at the preceding usage event. Startup failures use HTTP once; after exposed output, fail without replay. Legacy startup must pass through discarded tool deltas before selecting fallback. Apply model reasoning policy after legacy final assembly and before constructing continuation replay output. A failed tier-less HTTP retry must retain the caller's transport fallback classification. Only explicit endpoint unavailability may disable Responses; parameter rejections retain their route and diagnostic. See [lifecycle guide](../../../docs/development/responses-websocket-streaming.md).
WebSocket TLS must use an explicit per-connection Rustls crypto provider: dependency features enable both Ring and AWS-LC, so automatic provider inference can panic. Preserve bundled trust roots and certificate verification. Record served-tier evidence at completion boundaries, never while rebuilding continuation replay. Responses inline `file_data` must use MIME-prefixed base64 data URLs; normalize raw base64 at the wire boundary without rewriting stored history, and count decoded bytes for limits. See the [file-input contract](../../../docs/development/responses-websocket-streaming.md#inline-file-inputs).
Providers in `providers/<name>/mod.rs`. Use `anyhow::Result`, `tracing`, not `println!`. Provider-specific types stay local; shared go in `types.rs` or `provider/`. Keep provider helper import paths stable through the common/shared facades; cross-module implementation helpers use `pub(super)` rather than public exports. OpenResponses streaming wire parsing dispatches by `type`; keep hot SSE fields borrowed and update the wire fields and mapping together when adding events.
Native Responses `allowed_tools` uses object references derived from the serialized catalogue (type plus name or MCP server label), never bare tool-name strings. `providers/openai/request_builder.rs` owns the native Responses 16-token minimum, including auxiliary requests. Native GPT-5.6+ cache-enabled runtime reminders use a trailing developer role so implicit cache writes cover reusable user/tool history; keep legacy reminder shapes on other routes. Cache-read/write accounting is independent of local hints and diagnostics. Opt-in auxiliary `StablePrefix` caching marks only instructions on eligible native routes; keep interactive implicit caching. Cache comparisons advance only on foreground completion; keep them independent of replay lineage and out of standalone compaction. Parse comparison metadata independently of final content, including empty-output streaming fallback; see the [caching guide](../../../docs/tools/PROMPT_CACHING_GUIDE.md#openai-cache-comparison-diagnostics).

- Custom provider profiles match exact model IDs; explicit API formats select the wire backend without protocol fallback. Provider tool formatters return `Result<Option<Value>, LLMError>`; never hide serialization failures, and flattened provider extension maps must reject collisions with reserved wire fields before serialization. `LLMProvider::requested_prompt_cache_ttl` reports the effective Responses wire lifetime for gap advisories; custom `openai-responses` routes require `supports_prompt_cache_options = true`, with explicit profile `false` preserved. Other transports omit TTL options; breakpoints and comparisons remain native-only.

## OpenAI-Compatible Providers

- `providers/openai_compat.rs` owns the shared shell: `OpenAiCompatSpec` (per-provider consts/overrides) + `OpenAiCompatCore<S>` + `impl_openai_compat_provider!`. New compat providers implement a Spec (~50-200 lines), not a full `LLMProvider`; NVIDIA also accepts arbitrary explicit IDs and maps thinking through `chat_template_kwargs`. Model normalization happens in `core.prepare()`, not `convert_request()` — payload tests must call `prepare` first. `stream: true` is only inserted when `request.stream` is set. Providers with extra protocols (evolink Anthropic path, opencode) hand-write the provider over `OpenAiCompatCore` instead of using the macro. StepFun now hand-writes the native Responses API (`POST {base}/responses`, `input`/`instructions`/`reasoning.effort`/`max_output_tokens`, flat function tools) instead of the compat shell; keep its `from_config` 7-arg contract and `supports_non_streaming` override. Registration contract: keep the type name and 7-arg `from_config` consumed by `impl_standard_provider_constructor!` in vtcode-core (EXCEPTION: OpenRouter uses custom `OpenRouterProviderBuild` + `from_config_with_attribution` for the attribution opt-in; keep its 7-arg `from_config` as disabled-default compat). Responses function tools explicitly serialize `strict: false`, including fallbacks; keep Chat, hosted, and custom contracts unchanged. The Open Responses bridge maps authoritative plan-approval `ThreadEvent` variants to `vtcode.*` custom events for client parity. Provider error bodies are stream-read with a 16 KiB cap, then diagnostics use the bounded, secret-redacting sanitizer before metadata, display, or logs. Provider-owned child processes use the shared filtered environment, with only narrow GitHub-auth exceptions for Copilot. Copilot stdio EOF, timeout, and cancellation paths must clear pending calls; frames remain bounded. Copilot line reads delegate to commons `line_framing` with `IncludeLf`; preserve LF cap accounting for JSON-RPC lines and server-client headers. `ContextWindowProvider` carries discovered model capacity per provider instance; delegate every transport/capability method (including `supports_decisions`/`decide_choice`) and scope overrides to the selected model. Decisions is default-unsupported except for built-in direct OpenAI API-key instances at the parsed standard origin/base path; capability checks must do no credential discovery or I/O. Decisions uses a separate no-redirect client with existing timeout/proxy policy and fails closed on construction errors; never use the ordinary redirect-following client for evidence. Use endpoint-specific pricing for Decisions and keep auxiliary usage out of prompt-cache health; see [probe guide](../../../docs/development/decisions-probe.md). `ToolChoice::None` must disable callable tools on the wire. Copilot must send an explicit empty built-in allowlist to both CLI and session creation and distinguish that policy in its cached-client key; native Responses forced-function choices use the shared flat serializer. Ollama, StepFun, Merge Gateway (native/legacy), Meta, and Z.AI omit definitions because their transports do not enforce a none choice; retain historical call/result pairs. Standard OpenAI-compatible, Responses, Anthropic, and Gemini routes retain catalogs only with explicit none enforcement. See [provider audit](../../../docs/development/planning-provider-audit.md). Gemini explicit `cachedContents` segments are keyed by model/system/tools only, so `generate` and `stream` must share `send_generate_request_with_cache_recovery`: a stale name is dropped and retried once uncached. The API rejects `systemInstruction`/`tools`/`toolConfig` beside `cachedContent`, so a request whose built `toolConfig` is not the API default (constrained `tool_choice`, `VALIDATED` decoding, or server-side invocation flags) must skip the explicit cache (`body_tool_config_is_non_default`) and keep its config on the body; the segment entry survives for later default-config turns. Anthropic `speed` uses one resolver for both transports and refusal retries; configured preferences stay dormant on unsupported routes, explicit incompatible fast fails before sending, preview beta follows serialized speed, and `usage.speed` is logged only at completion. Custom auth setup also marks non-native routes even without a credential refresh handle. Anthropic Claude 4.6+/5.x: no assistant prefill and no forced `tool_choice` (both 400; gated by capability profile flags, fallbacks included); thinking is adaptive, manual budgets resolve to adaptive on adaptive-only profiles; replay assistant blocks in recorded `anthropic_block_order`; streamed refusals carry `stop_details`; server-side fallbacks default to `"default"`, and effort is sent only when configured. The extended-cache-TTL beta follows the effective breakpoint TTL via `messages_cache_ttl_for_profile`, so budget-continuation profiles promote the messages breakpoint and its beta header together.
